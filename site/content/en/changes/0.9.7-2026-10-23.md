## 0.9.7 "Polaris" – 2026-10-23 (beta)

### New
- **Lux Guard** (`luxos-guard`): checks files from the internet, mail, chat, LuxDrop and USB when they are run (fanotify in the kernel, marks only on watched files – other programs pay nothing). Risky ones: a dialog "Don't Run / Run in Sandbox / Run Anyway"; critical ones (deleting the home folder or a disk, `dd`/`mkfs`/`shred` on a disk, encrypting files in a loop, hidden code, disabling protection…): never outside the sandbox. Own rules without an antivirus (1 false alarm on 35,980 system scripts and programs). A read-only snapshot of `/home` every hour (btrfs, hourly for 24 h + 7 days), file restore in the Lux Guard window or with `luxos-guard restore`. Documentation also for LuxAI: `docs/luxos/guard.md`.
- **Captive portal sign-in** (hotel, train, airport): in the "portal" state `luxos-hub` opens the sign-in page by itself, once per connection (again via the "Sign in" button in the notification), in a one-off Firefox window with an empty in-memory profile (no cookies, passwords, history or add-ons of the user, deleted on close); the window closes once you are connected.
- **LuxOS kernel `linux-luxos`** (https://github.com/luxopes/luxos-kernel): stable Linux from kernel.org with a verified signature, Arch's configuration (all drivers) + `config-luxos` (BBR, `NR_CPUS=512`, THP on request). GitHub Actions builds a new version every 6 h, boots it in QEMU with ~50 drivers and releases it with a provenance attestation; LuxOS takes it after verification (`scripts/fetch-kernel.sh`) and signs it. New installations and the live ISO have it right away; older installations switch from `linux-zen` by themselves after the update (`luxos-care kernel-switch`: headers for DKMS, initramfs and DKMS module checks, `linux-zen` stays as "LuxOS (previous kernel)" and the new kernel gets 3 boot attempts).
- **Control Center, Calendar and `luxos-hub` in LSL** (LSL 0.10.6, one program instead of three in Python): 23 MB less memory (PSS), 7× less CPU at session start, the same response after a click.

### Fixes
- Store: "Could not check for updates" when a LuxOS Care check was running at the same time, or after an interrupted check (lock in the temporary database). The checks now wait for each other, a leftover lock is cleaned up, and the Store shows the real reason for the error.
- ELAN fingerprint readers (e.g. 04f3:0c4f, Acer Aspire 7): "Calibration failed!" – the own `libfprint` package gives calibration up to 100 checks (5 s) instead of 10.
- LuxAI 1.0.0-11: bug reports list LuxOS packages again (query via `lux-engine` instead of the non-existent `pacman`).

### Changes
- LuxOS repositories and downloads are at **https://luxos.lux-ai.cz** (`/repo/`, `/download/`); the old address `lsl.lux-ai.cz/luxos` still works, and migration of old configurations rewrites it.
- `lux update` runs other packages' steps after an update (`/usr/lib/lux/after-update.d`).
- `lsl` 0.10.6 in `[luxos-apps]`.
- `./build.sh one PACKAGE` builds a single package into `out/single` (repository unchanged).

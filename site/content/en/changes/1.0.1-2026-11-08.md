## 1.0.1 "Sirius" – 2026-11-08 (beta)

A bug-fix release of 1.0.0 "Sirius" with a new ISO: stability (fork bomb, `/tmp` on disk), firewall, Store descriptions and screenshots, Weather, windows like in macOS, emoji, printing and scanning. Installed systems get everything with `lux update`. Mail stays in the staging test channel for now (its changes are under Coming soon), and Lux Code stays at its previous version in the stable channel.

### New
- **/tmp lives on the disk instead of in RAM**: LuxOS swaps only to zram, so everything in a tmpfs `/tmp` always took real memory – forgotten files (4.9 GB in one case) even filled the swap. `/tmp` is now on the (encrypted) system disk in its own top-level Btrfs subvolume `@tmp` (`nodev,nosuid`, programs can still run from it), not part of system snapshots, rollback or backups, and emptied at every start. New installations get it from the installer; existing ones switch over by themselves from the next start, without any commands. Non-Btrfs roots, custom `/tmp` setups and the live ISO are left alone.
- **LuxOS Store: a full description and real screenshots for every LuxOS app**: all 29 LuxOS apps in the release catalog (LuxAI, Terminal, Text Editor, Maps, Weather, Calculator, LuxDrop, Backups, Vault, Firewall, Lux Guard and more) now have a long description – an intro and a list of their real features – in English and all 12 other LuxOS languages, shipped as AppStream metainfo in each package. 69 screenshots (1–3 per app, small WebP files) are generated automatically from the apps themselves.
- **Weather: a live sky that matches the weather and time of day**: instead of a plain gradient, Weather draws its own scene – clear, partly cloudy, overcast, fog, drizzle, rain, thunderstorm and snow, each by day, night, dawn and dusk – with the sun, the moon in its real phase, twinkling stars, drifting clouds, falling rain and snow and distant lightning. White text keeps good contrast. It is light on the battery: only moving parts are redrawn, and the animation stops when the window is inactive or minimized, in Battery Saver, with reduced motion, or when ⋯ › Animated background is off.
- **Anonymous count of active installations – like Fedora's "countme"**: at most once per calendar week, when `lux` is already downloading package lists as root, it sends one small extra request with **only** the LuxOS version, architecture, update channel and a rough installation-age group. No ID, computer name, hardware, app list or user data; it never delays an update and is not sent from the live ISO, containers or user sessions. It is on by default and can be turned off in Software Update › Privacy, with `lux config countme off`, `countme = false` in `/etc/lux/lux.conf` or in the installer; the totals are public on the usage page.
- **Firewall on from the start – and it breaks nothing**: an external audit found the firewall off and services such as Postgres, dev servers, LuxDrop and Steam listening on all interfaces. LuxOS now has its own firewall, switched on right after `lux update` (no restart) and on new installations, in its own nftables table `inet luxos` – Tailscale, Podman, libvirt, Docker and ufw are left alone, and if rules fail to load the network stays open and `luxos-firewall status` says why. Only new incoming connections are filtered; DHCP, IPv6, mDNS, printer and scanner discovery, local ping, and LuxDrop, Steam Remote Play, KDE Connect and Syncthing from the local network keep working. When a program wants to accept connections, a notification asks **Allow / Keep Blocked**; there is a new **Settings › Firewall** panel and the `luxos-firewall` command.
- **New windows open in free space, otherwise in a cascade – like in macOS**: the first window goes to the center, the next ones to free space, and when there is none, each new window of the same app is offset by 28 px from the last, so a new window never lands exactly on top of another. Dialogs, windows with their own position and restored windows stay where they were; old profiles with the former centered default switch once at login.
- **Alt+` switches between the windows of the current app** (the key below Esc): the same switcher with previews as Alt+Tab, but only with the windows of the app you are in; Shift+Alt+` goes backwards. It works by key position in every keyboard layout, and Super+` now also works on the key below Esc in the Czech layout.
- **Option "Group windows by application in Alt+Tab"** (Keyboard Shortcuts › Windows, off by default): Alt+Tab shows each app only once (with its last used window); while holding Alt, the Down arrow or ` shows the windows of the selected app and the Up arrow returns to the app list.
- After a window manager update, `luxos-hub` replaces the running xfwm4 with the new version by itself (`xfwm4 --replace`, windows stay in place), so the changes apply without logging out. Closing the last window in the Alt+Tab switcher while switching no longer crashes the window manager.
- **Emoji & Symbols – typing emoji like in Windows and macOS**: **`Super+.`** or **`Ctrl+Super+Space`** opens a small emoji panel next to the mouse pointer in any app (also findable in Launchpad and Search as **Emoji & Symbols**), in light and dark. Search works instantly by names and keywords in the system language and in English, ignoring accents and case; there are tabs for recently used and categories, and a remembered skin tone. **Enter** or a click inserts the emoji where you were typing and closes the panel, **Shift+Enter** keeps it open, **Esc** closes it; the original clipboard content is restored afterwards.
- **The `line` command**: picks lines of output or a file instead of `sed -n` or `head | tail` – `command | line 5`, `line 1,10`, `line 1-10`, `line 5-` (to the end), `line -1` (the last line), `line 3,7-9 file`. Without negative numbers it streams and stops right after the last selected line.
- **Mirror and Extend in Control Center**: with two or more monitors connected, Control Center shows a **Displays** section under brightness with **Mirror**, **Extend** and, on laptops, **External only** buttons; the active mode is highlighted and the current setup is described. No popup appears when a monitor is connected, switching is instant, and the mode is remembered per set of monitors. Mirroring no longer crops anything: all monitors share one resolution (the best common one with the same aspect ratio, or scaled), and Extend returns to 1:1 and restores the saved layout.
- **Terminal: text selected with the mouse is copied to the clipboard right away**: after releasing the left button, the selection (drag, double-click a word, triple-click a line, Shift+drag in mouse apps like mc or htop) is also copied to the clipboard, so you can paste it elsewhere with Ctrl+V – like terminals in macOS and Windows. It can be turned off with `copy_on_select = false` in the `[terminal]` section of `~/.config/luxos/terminal.conf`.

### Fixed
- **The notification bell in the bar shows a red dot when you have unread notifications**: the old blue dot was recolored by GTK and almost invisible; the bell now draws its own sharp red dot on light and dark bars (crossed-out bell with a dot in Do Not Disturb), which disappears after opening the bell menu. A notification replaced by an app also updates its history entry instead of piling up new ones, and notifications closed by the app are marked as read.
- **Updates no longer require merging configuration files by hand**: after `sudo lux update` users saw "New config files to review: /etc/lux/lux.conf.luxnew" without knowing what to do. LuxOS now merges new versions of configuration files right after each transaction, using the old package version as the base: in key = value files your values are always kept (and `channel` and `countme` in `lux.conf` always belong to you), new keys, sections and comments are added. The result is written atomically with a `.lux-old` backup; only real conflicts are left for `sudo lux config-diff`.
- **Rolling back to an earlier system state (`luxos-care rollback`) no longer reports an error at the end.** The rollback worked, but the command ended with a Python error while writing the history and looked like it had failed.
- **Wi‑Fi QR code: the Copy button is visible again**: the header button showed no icon and was practically invisible. It now shows its icon and copies the QR code image to the clipboard; a test checks the visible icon and the clipboard image.
- **LSL IDE**: in an English system some headers and messages were still in Czech – now everything goes through the IDE translations (a test makes sure every text has an English translation). The Symbol panel, completion, signature help and Go to Definition now find functions from local modules instead of "Unknown symbol", and the default window no longer exceeds small 1280×800 screens (at most 90% of the work area).
- **Printers and scanners: scanner types in plain words**: the subtitle showed raw, untranslated SANE types such as "Escl network scanner". It now shows translated labels such as "Network scanner (eSCL/AirScan)", "Multifunction device", "Flatbed scanner" or "Film scanner", and the connection (network/USB) for more scanner types.
- **LuxAI: the agent status line shows a short path**: instead of the full working folder path it uses `~` for the home folder and shortens a long middle part to "…" (e.g. `~/Projects/…/files/python`).
- **Maps, Weather, Camera, the setup assistant, Printers and Scanning run from source load their own modules**: older installed modules used to take precedence (even in tests); now the script's own folder comes first and the installed modules are only a fallback.
- **Weather: no more Fahrenheit in Europe**: an English LuxOS has `LANG=en_US.UTF-8`, and Weather took "US" to mean the USA – showing °F, mph and inches even in Prague. Now a plain `en_US` only means default English: the country of your first saved place and then your time zone decide, and °F is used only in the US and the few other countries that use it. On the first open Weather asks once **Which units do you want to use?** (°C / °F, with the detected one preselected); you can change it anytime in ⋯ › Units, and manually chosen units are kept.
- **Lux Guard: "Run in Sandbox" no longer scares you with a popup terminal**: since the previous fix every text program and script started in a terminal that stayed open – confusing for ordinary users. A terminal now opens **only** when you are clearly working in a terminal, when the script clearly asks for input, or for launchers with `Terminal=true`. Other text programs run in the sandbox **without any window or terminal**; their output is saved to a private file and one calm notification says whether the program finished safely in the sandbox. GUI programs still run in their own sandbox window.
- **LuxOS Store: the LuxOS Apps section shows the real LuxOS apps, and the update spinner turns on the first open**: the section used to show libraries like "VTE Terminal for GTK3/GTK4", the `luxos-docs` package and Lux Simple Lang, while Terminal, Text Editor, Maps, Weather, Calculator, Backups, Vault, LuxDrop and other LuxOS apps were missing. It is now filled from a signed LuxOS app catalog built when the repository is published, so the Store also knows apps that are not installed. The spinner during the update check now turns right away.
- **Lux Guard: "Run in Sandbox" no longer opens a terminal needlessly**: every script and `.desktop` launcher used to start in a terminal that stayed open – even GUI Python apps, zenity/yad installers and launchers with `Terminal=false` – while command-line programs ran in their own Xephyr window and lost their output. Lux Guard now recognizes the file type: GUI programs, AppImage, jar, exe, GUI scripts and `Terminal=false` launchers run only in their own window **without a terminal**; text programs and scripts run in a terminal that stays open for their output.
- **Security: the Canon UFR II driver left `/etc/cngplp2/account` and `options` writable by everyone**: any user could delete or fake another user's files there (including department IDs and print passwords). The folders now have mode 1777 (sticky bit, like `/tmp`), so writing still works but nobody can delete or overwrite other users' files; older installations are fixed by the package's install script.
- **Security: kernel addresses only for root**: `kernel.kptr_restrict = 1` – user programs see zeros in `/proc/kallsyms`, while root (perf, bpftrace, the `scx_lavd` scheduler) still sees real addresses. It applies right after the update, without a restart.
- **USB printers are set up only by LuxOS**: the automatic setup from system-config-printer was faster than LuxOS and picked a worse driver (Canon MF4100: CARPS2 instead of UFR II LT). It is now disabled and the LuxOS helper adds the printer with a better driver choice; the LuxOS USB printer rule, which had never actually run, now runs last.
- **Scanning: "open of device … failed: Invalid argument"** (Canon MF4100 and other USB pixma scanners): a scanner can be opened by only one process at a time, and scanner discovery collided with reading its options. `scanimage` calls now take turns, and an open that fails because of another process is retried 4 times.
- **Security: LuxAI administrator mode no longer gives passwordless root to other programs**: after turning on "No password" in LuxAI › Settings › Agent permissions, LuxAI wrote a polkit rule that allowed root without a password for **any** program in the user's session, not just LuxAI. Now no polkit rule is written and old ones are removed right on update (no logout needed); you enter the administrator password once and polkit remembers it for about 5 minutes **only for the process that entered it** (the running LuxAI), every other program gets a password dialog, and the helper additionally checks that it was started by a genuine, non-debugged LuxAI.
- **Security: LuxOS Care no longer checks for updates in a predictable folder in `/tmp`**: the root update check used `/tmp/lux-checkupdates-0`, which any user could create in advance to make update checks and automatic updates fail until a restart, or make root write into a foreign folder. Root now uses its own `/var/lib/luxos-care/checkupdates`, and the fallback refuses folders it does not own, links and folders writable by others.
- **A fork bomb no longer freezes the computer – not after an update while running, not outside the Terminal**: the earlier protection failed on a real laptop because LuxOS Care updated the Terminal during the session and the old, unprotected Terminal process kept receiving every new window. The Terminal service now has a new name, so **every new window and tab is protected right after an update** even next to the old process; every tab has process and memory limits, and a system-wide guard stops runaway process trees before memory runs out.
- **The progress after login no longer stutters and looks like the system start**: instead of a stuttering spinner, the same thin rounded bar as the boot splash appears where the password field was, so boot and login look like one whole. The bar follows the real progress of the session and finishes while the desktop fades in. The stutter came from a busy check loop sharing time with drawing, a lowered priority, and the screen running twice.
- **Captive portal sign-in can be reopened after closing the window**: in a hotel or on a train the sign-in window opened only once. Now, as long as the network blocks the internet, the "!" icon in the bar says "Sign in to the network for internet access" and opens the sign-in window (also for portals behind VPN DNS), Control Center has **Sign in to network "<network>"…**, and the notification with **Sign In** stays until closed and reminds you again after 5 minutes (then less and less often) – without ever reopening the window on its own.
- **WebGPU works in Chromium**: Chromium on Linux does not enable WebGPU without Vulkan flags, so pages such as browser games reported missing graphics. LuxOS creates `~/.config/chromium-flags.conf` with `--enable-features=Vulkan` and `--enable-unsafe-webgpu` once – only if you do not have one (your own flags are never changed).

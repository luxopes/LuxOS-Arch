## Coming soon

So far only in the staging test channel (`channel = "staging"` in `/etc/lux/lux.conf`).

### New
- **Typing Vietnamese** (`luxos-desktop` 1.1.0-107, `luxos-i18n` 103, `luxos-docs` 103): Keyboard Layouts has a new **Input Methods** section with a **Vietnamese** switch and a **Typing style** choice (Telex, VNI, VIQR); searching "Vietnam" in Add Layout… ("Vietnamese (Telex, VNI)") turns it on too. Vietnamese is typed on an ordinary keyboard with the fcitx5 input method and the Bamboo engine (Telex: `Vieejt Nam` → "Việt Nam"), not with another layout. It is set for your account only, at once and without an administrator password; right after turning it on and after every login you type Vietnamese, **Ctrl+Space** switches between English and Vietnamese (Super+Space stays Search) and the menu bar shows the input method icon. It also works in GTK apps that are already open, in Firefox and in LuxOS Terminal; accounts with Vietnamese as their language (`vi_*`) get it automatically at their first login. For other users fcitx5 does not run at all, and users who set fcitx5 up themselves are left alone. Qt apps need `lux install fcitx5-qt`. From the command line: `luxos-input-method status|enable|disable|style`; new texts in 12 languages, help (Keyboard).
- **Mail: write, reply, forward and send mail – and messages that look like messages** (`luxos-mail` 1.0.0-9, `luxos-i18n` 67, `luxos-docs` 52): Mail now sends mail (SMTP), not only reads it. **New Message** (Ctrl+N), **Reply** (Ctrl+R), **Reply All** (Ctrl+Shift+R) and **Forward** (Ctrl+Shift+F, with the original attachments) open a message window with From (account picker), To/Cc/Bcc with address suggestions (people you wrote to and senders in your local mail), subject, text and attachments (button, Ctrl+Shift+A or drag and drop; list with size and ×, a warning above 25 MB). Send with the button or Ctrl+Enter; replies quote the original ("On … wrote:" with `>`), keep the thread and mark the original as answered (forwarded) on the server. A signature per account, `mailto:` links with subject and body. **A written message is never lost**: it is saved on the computer 1.5 s after every change (after a crash the window comes back), to Drafts on the server after 30 s (replaced by each new version, removed after sending); closing asks "Save this message as a draft?". Without a connection the message waits in the **Outbox** and is sent automatically (30 s, 1 min … at most every 15 min, at once when the network is back); permanent errors (refused recipient, sign-in, message too large) say exactly why and nothing is sent, an Outbox message stays "Not sent" with the reason and a notification. A copy goes to Sent on the server – except for Gmail and Microsoft, which save it themselves. Own SMTP client in LSL: implicit TLS 465 and STARTTLS 587 with certificate and SNI checks, AUTH PLAIN/LOGIN, XOAUTH2/OAUTHBEARER with Google, Microsoft and LuxAI tokens, SIZE checked before sending; RFC 5322 messages in UTF-8 (RFC 2047 headers, quoted-printable/base64, RFC 2231 file names, no Bcc header). **Received mail is shown properly** (links were not clickable and formatting was poor): messages are shown in a locked-down WebKitGTK (already part of LuxOS) – HTML mail with its layout, colours, tables and attached pictures (on white paper also in dark mode when it has its own colours); plain text with clickable links, quotes as indented blocks with a coloured bar, a dimmed signature and ASCII tables in monospace. Links open in your browser (mailto: in a new message) and show their real address on hover. Remote images and tracking pixels stay blocked until **Load Images** or **Always from <sender>**; scripts, event handlers, forms, iframes, external styles and dangerous links are removed and the message page forbids network access (Content-Security-Policy), JavaScript off, no cookies. Attachments: Open / Save As…, picture previews under the text; Ctrl+F finds in the message, Ctrl+P prints, Ctrl+plus/minus/0 zooms. Ctrl+R is now Reply (like Mail on macOS); get mail with F5 or Ctrl+Shift+N. Also fixed: after a background sync rebuilt the message list, the list lost the keyboard focus and the arrow keys did nothing.
- **Mail: ready for Google app verification**: before you sign in with Google (or Microsoft), the Add Account window explains what Mail uses the access for – only to download, show and organise mail on this computer; neither your mail nor your sign-in is ever sent to LuxOS or anyone else – with a **Privacy Policy** button (luxos.lux-ai.cz/privacy). **Removing a Google account now also revokes Mail's access at Google** (token revocation, RFC 7009 – Mail disappears from myaccount.google.com/permissions); offline, the account is still removed from the computer. The remove confirmation for provider sign-ins no longer talks about a "password". The website has new pages LuxOS Mail (`/mail/`), Privacy Policy (`/privacy/`, with a section on Google user data) and Terms of Use (`/terms/`) in English and Czech, linked from the footer and checked by `scripts/check-site.py`. The verification steps for the project owner, a 120×120 logo and demo video scripts are in `docs/google-verification/`.
- **Mail: "Sign in with Google / Microsoft" instead of an app password**: adding Gmail with an app password is too complicated for most people and Outlook.com does not accept passwords for IMAP at all. Mail now signs in with the provider like Thunderbird (OAuth 2.0 for native apps, RFC 8252): for a recognised provider the Add Account window shows one main **Sign in with Google** / **Sign in with Microsoft** button (neutral text, no logos) and the password field disappears (for Google it stays under **Use an app password instead**). Google Workspace and Microsoft 365 on your own domain are detected by MX. The sign-in opens your browser, Mail listens only on `127.0.0.1` with PKCE and a random `state`, the refresh token is stored only in the keyring and the access token is kept only in memory and renewed automatically. The browser shows a small "You are signed in – back to Mail" page in the LuxOS look and the Mail window comes back to the front. When the provider stops accepting the sign-in (password change, revoked access), a calm yellow bar offers **Sign in again…** and Mail does not retry on its own. Providers are data in `/usr/share/luxos-mail/oauth-providers.json` (administrators can override them in `/etc/luxos/mail-oauth.json`; Yahoo/AOL are prepared but off). **The client IDs are still empty** – until the apps are registered with Google and Microsoft the app-password help stays; the IDs can later arrive without a new package from `https://luxos.lux-ai.cz/mail-oauth.json` (only public client IDs, never endpoints; `{"remote": false}` turns this off). Sending (SMTP) is not in Mail yet, but the sending permissions are requested already. Covered by tests with fake Google, Microsoft and IMAP servers, including a check that no tokens end up in files or logs.
- **Mail: sign in with your LuxAI account – LuxAI mailboxes without a password**: when a LuxAI account is signed in on LuxOS, the first Mail screen offers **Continue as <name>**. Mail asks the LuxAI server which mailboxes the account may use (e.g. `info@lux-ai.cz`) and adds one with a single click – no password and nothing in the keyring: before every connection the background service gets a short-lived token (15 minutes, bound to the account, this computer and the mailbox) and signs in with SASL OAUTHBEARER or XOAUTH2; the account session token goes only to the LuxAI server, never into arguments, Mail files or logs. If the account has no LuxAI mailbox, the normal add-account screen opens with the e-mail prefilled, as does **Use another account…**. Signing out of LuxAI, changing the password or removing access on the server stops new sign-ins at once; an expired sign-in shows **Sign in…**. New menu item **Add LuxAI Mailbox…**. The server side (`server/mail-oauth`: token API, Dovecot 2.4 with OAuth2 and public IMAPS, Postfix submission, fail2ban filters, deploy and rollback scripts) is tested locally and not deployed yet.
- **Mail – LuxOS's own lightweight mail client with instant new-mail notifications** (new `luxos-mail` package in `[luxos-apps]`; phase 1: reading and notifications): a small background program `luxos-mail-service` (no GTK, about 17 MB, starts with the session) keeps one connection per account and thanks to **IMAP IDLE** the server announces new mail itself – a **"New mail from …"** notification with subject and preview arrives within a second, **Open** opens Mail right at the message, several messages give one summary, already read or announced messages stay quiet and Do Not Disturb is respected. Without IDLE it checks every 5 minutes and reconnects right after the network returns or the computer wakes up. The unread count shows on the Dock icon. **The window** has three columns like Mail on macOS (mailboxes, message list with unread dots and attachment clips, message), light and dark, opens in 0.2 s even with a thousand messages, works offline from a local cache and is fully keyboard-controlled (arrows, Enter, Delete to Trash, Ctrl+Shift+U read/unread, Ctrl+F filter, Ctrl+R fetch). **Adding an account** needs only an e-mail address and password: server settings are found automatically like in Thunderbird (provider autoconfig, ISPDB, MX, DNS SRV, verified guessing), with manual setup as a fallback. **Security:** TLS always with certificate verification (no "continue anyway"), the password only in the keyring, never in a file; a wrong password is not retried; HTML messages shown as text without scripts, images or remote content (no tracking pixels). IMAP4rev1/rev2 with CONDSTORE and QRESYNC, MIME with Czech, German and Ukrainian character sets, attachments can be saved. Writing, replying and sending come in phase 2; for now Ctrl+N and `mailto:` links offer to copy the address for webmail. Mail is part of the base installation, Thunderbird stays in the Everyday set (existing systems: `lux install luxos-mail`). Written in LSL, with tests against a test IMAP server and a virtual screen; documentation in `mail.md`.

### Fixed
- **Calculator: deleting, live result and editing after "="** (`luxos-desktop` 1.1.0-108): ⌫ after an operator (e.g. `425 ×`) deleted nothing – now it removes the operator and then the digits of the previous number, also inside parentheses. A grey live result of the expression being typed is shown under the number (`= 17`). ⌫ right after "=" (also after "Error") brings the whole expression back for editing with the last number editable; an operator after "=" still continues with the result.
- **LuxAI: a pasted image is visible with the message, answers with thinking are no longer cut off** (`luxai` 2.1.0-3): an image pasted with Ctrl+V was sent, but the attachment chip above the input was invisible and in the sent message the thumbnail sat above long text, out of view – now it is below the message text, framed. In Agent mode with a higher thinking level, answers ended with "The answer was cut off (length limit)" because thinking used up the whole answer limit; the limit now includes a thinking reserve based on the chosen level.
- **More detailed `man lux`** (`lux` 0.3.0-33): the manual page has new sections Sources (order repositories → LuxOS → Flathub → AUR), Community packages (AUR: script check, sandbox, `--system`), Updates (snapshots, held packages, stable/staging channel), all `/etc/lux/lux.conf` keys and repositories with an example, Environment, a table of pacman command equivalents and Troubleshooting (locked database, signatures, configuration errors, undoing an update); plus `list --explicit`/`--orphans`, `owns`/`owner`, `config engine`, the terminal store keys and more examples.
- **Safe graphics on computers with an old BIOS** (ISO; reported on a Gigabyte P55A-UD3 with an RTX 3050): the "LuxOS – safe graphics" entry on computers without UEFI stopped at text ("Started Accounts Service.") – without a graphics driver there was no screen for the desktop to start on (UEFI provides one, BIOS does not; Arch no longer has the VESA fallback drivers). Safe graphics on BIOS now sets a 1024×768 screen from the BIOS (`vga=791`, `gfxpayload` in GRUB) and the desktop starts. Tested in a virtual machine with SeaBIOS.
- **Realtek RTL8723DE Wi-Fi (HP laptops) after restarting from another system** (`luxos-drivers` 1.0.0-13, `luxos-i18n` 102; reported on an HP 15-rb): after a restart from another Linux (e.g. Debian) the Wi-Fi of this chip does not start (`mac power on failed`, error -16) and Wi-Fi is missing from the top bar altogether; only a full power-off helps. It is a chip and kernel bug (reported on linux-wireless, no fix yet). LuxOS now releases the chip's Bluetooth and Wi-Fi before every restart and shutdown, so it does not get stuck after restarting from LuxOS. When it arrives already stuck, a notification after login says what to do (shut down, hold the power button for 30 s, turn on).
- **One loading bar with automatic login** (`luxos-desktop` 1.1.0-106, `luxos-branding` 1.1.0-35): on the live ISO and with automatic login turned on, two bars appeared one under the other at the end of startup – the boot screen bar (Plymouth) and below it the desktop loading bar in the place of the password field. Desktop loading now continues right in the boot screen bar: same place, same colour, from where startup ended. Nothing changes with the login screen.
- **Window button size can be chosen** (`luxos-desktop` 1.1.0-105, `luxos-i18n` 101, `luxos-docs` 102): **Displays › Scale › Window buttons** offers Automatic (default – follows the scale, one size bigger on a touch screen) / Standard / Large / Larger. It changes only the close, minimize and maximize buttons (and the title bar), not text or the rest of the system – the automatic size does not suit everyone. Command `luxos-appearance wm-buttons auto|standard|large|larger`; if a frame variant is missing, the next smaller one is used.
- **Touch: close Launchpad with a tap, scroll the list with a swipe, bigger window buttons** (`rofi` 2.0.0-1.5, `luxos-desktop` 1.1.0-104, `luxos-docs` 101; tester feedback on an ASUS ROG Flow Z13): a Launchpad (or Search) opened by accident closes with a tap anywhere outside it – tapping the on-screen keyboard still keeps it open (before, only Esc closed it). Swiping up or down scrolls the app list by a page – with the on-screen keyboard only two rows are visible and further apps could not be reached. On a touch device windows get one size bigger close, minimize and maximize buttons (`-hdpi` title bar theme, `-xhdpi` from 125 % scale) so a finger hits them; they go back to normal when a touch monitor is unplugged.
- **Terminal starts again after an update** (`vte3` 0.84.2-1.1): Arch released a new `simdutf` library today (`libsimdutf.so.37`) and LuxOS's VTE (with SIXEL images for Terminal) needed the old `libsimdutf.so.36` – after `lux update` or on a fresh install, Terminal did not start. VTE is now 0.84.2 like in Arch, built against the new library; SIXEL images keep working.
- **Mail: an @lux-ai.cz address signs in with the LuxAI account, not a password** (`luxos-mail` 1.0.0-17, `luxos-i18n` 97): after you enter a LuxAI mailbox address in Add Account, Mail no longer tries a password over IMAP (it ended with a confusing wrong-password message) but offers the LuxAI mailboxes – right away or after signing in to the LuxAI account. Without the LuxAI Account app (`luxos-account`, e.g. Mail on another distribution) it says what is missing.
- **Mail: fixes from the final review before the stable release** (`luxos-mail` 1.0.0-16, `luxos-i18n` 91): a text part with a file name (sent inline by some programs) is shown in the message – before it was neither visible nor listed as an attachment; the unread count of the Inbox (list, Dock, notification) also counts messages older than the latest 500 downloaded; a draft whose attachment was deleted meanwhile is no longer lost when you close it with Save – the window stays open with a message (drafts lost this way before open again at start); closing the window while a draft is being saved to the server keeps the local copy until the server confirms it; deleting a draft while it is being saved and changing From after saving no longer leave an orphaned copy in Drafts; a message from a removed account no longer silently switches the sender – the window says so; Reply / Reply All before the message has downloaded waits for it (before, the reply went only to the sender, without Cc and quote); a message queued in Outbox while offline no longer closes the window without a word; addresses without a dot in the domain (user@server) are accepted; “Ref:” in a subject is not taken as a reply; address suggestions include new recipients without restarting Mail; temporary copies of attachments (Forward, opened attachments) are cleaned up; new mail behind a home router arrives right away (IDLE is renewed every 9 minutes instead of 25); a stray “=?” in a subject no longer stops decoding the rest; a message interrupted by a service crash while sending is not resent on its own (it could arrive twice) – you get a notification; the Answered flag after sending never hits another message after a mailbox was recreated; counts of other folders load in one round trip.
- **App Studio and Icon Studio** (`luxos-app-studio` 1.0.0-3, `luxos-icon-studio` 1.0.0-3): The build record is kept outside the project folder and bound to the built program, so a copied or downloaded project is never run, installed or exported without its own build. A broken `package/lux.json` is refused when you open the project. Before, the project stayed half open and changes were not saved. Install writes its record before the first file, so uninstall also cleans up an interrupted install. Install refuses a name that would hide an existing command in the Terminal. `~/.local/bin` or the export folder can be a link to a folder. Saving app details keeps .desktop keys you added by hand. The editor note says when your work is saved. Icons exported from Icon Studio can be read by everyone (0644), so they show up after `lux install`.
- **Mail: fixes from a visual review** (`luxos-mail` 1.0.0-15, `luxos-i18n` 1.0.0-86): dates in the message list and header follow Mail's language even when the system has only an English locale (Czech Mail showed "Sunday" and "11/16/26 10:00"; now "středa", "21. 9.", "ne 22. 11. 2026 11:00", German "Mittwoch" etc.), sizes with a decimal comma where the language uses one; fixed-width HTML messages (newsletters, 600–700 px notification cards) are scaled to the reading pane instead of being cut off on the right with a horizontal scrollbar; a wrong password no longer appends the English server text "[AUTHENTICATIONFAILED] …" – known IMAP response codes (EXPIRED, UNAVAILABLE, LIMIT, PRIVACYREQUIRED …) are translated and the raw text is only under "Details"; keyring unavailable: Mail tries to start it and explains what to do instead of "secret-tool: Error calling StartServiceByName…"; adding an account offers a provider quick pick (Gmail, Outlook, Seznam, iCloud, Other), a tidier server form (Incoming/Outgoing mail sections, wider security menu) and a readable error box; toolbar buttons are disabled until an account exists; Czech wording unified.
- **Icon Studio: the window fits the screen** (`luxos-icon-studio` 1.0.0-2): Icon Studio opens no larger than the work area (it overflowed 1366×768 screens).
- **App Studio: installing never overwrites or deletes another app's icon of the same name** (`luxos-app-studio` 1.0.0-2): installing refuses a foreign icon just like a foreign program, uninstalling removes only files it wrote, and a summary with a line break cannot add another key to the launcher.
- **Mail: translated message about a connection lost right after handing the message to the server** (`luxos-i18n` 84).
- **Mail: a message with broken HTML no longer freezes the app; large and unusual messages open quickly and correctly** (`luxos-mail` 1.0.0-14): a message with an invalid HTML attribute (`>` inside a tag) made the HTML cleaner loop forever – the window froze, and froze again after a restart because the message reopened by itself. A message with thousands of file-name parts (RFC 2231) was sorted in quadratic time and blocked the background service for tens of seconds (now linear: 20,000 parts in under a second). A nested part whose boundary starts with the parent's boundary was split wrongly; HTML with an unclosed `<head>` lost all text in the preview. Addresses per RFC 5322: a comma inside an encoded display name no longer creates a fake extra sender, a quoted name containing “<…>” no longer replaces the address, a group with a quoted name no longer corrupts the first address, and an IPv6 address literal (`user@[IPv6:2001:db8::1]`) is no longer cut (groups, quoted strings, comments, domain literals; encoded words are decoded only after splitting). Protection against a faulty server: limited IMAP line length and reply size, DNS SRV records only with a valid server name.
- **Mail: no double sending and no lost message in the Outbox** (`luxos-mail` 1.0.0-14): when the connection dropped right after the message was handed to the server (no reply), Mail sent it again by itself – now it marks it "may have been sent, check Sent" and you decide. When the service stopped before taking over the message, it stayed both in the compose window and in the Outbox and went out by itself after 10 minutes (twice after pressing Send again) – now it stays only in the window. The compose window no longer stays in "Sending…" forever when the service does not start. In the Outbox the selection shifted when another message was queued, so Delete / Send Now hit a different message; a message opened from the Outbox for editing was lost when the window was closed without changes; a draft that failed to save on the server was dropped on close. Without UIDPLUS the server also deleted messages another program had marked as deleted; flagging or deleting from an outdated list (mailbox re-created meanwhile) could hit a different message – now it is refused and the list refreshes. Two attachments with the same name no longer overwrite each other when forwarding, removing an account checks its id, and Mail no longer quits after closing a compose window while the main window is open again.
- **Mail: after moving a message to the Trash the reading pane no longer shows the header of one message with the text of another** (`luxos-mail` 1.0.0-10): a real case on Gmail – after deleting a message (or deleting it permanently in the Trash) the next message was selected and the pane showed its subject, sender and date but the text of the previous message (e.g. the header "Hi" with the text of a different e-mail, or "Hello from LuxOS Mail" with Google's security alert). When the new message's text was not on the computer yet, "Loading…" went into a hidden text field while WebKit kept showing the old document. Now the pane is cleared at once on every selection change (including the WebKit document), every text download carries a selection token and a late text of an earlier selection is dropped; a message text is valid only together with the mailbox's UIDVALIDITY (a mailbox that was deleted and created again is refreshed at once, an old text is never stored under the same UID). Also fixed: opening a message in a folder that has not been downloaded yet (`luxos-mail --open`) now selects it after the sync.
- **Mail: signing in with a Microsoft account (Outlook.com) ended with "User is authenticated but not connected"**: the browser sign-in and consent worked, but adding the account failed. Microsoft sends this when it accepts the token but does not open the mailbox (an alias instead of the main address, a token for the wrong resource, IMAP turned off for the Outlook.com account, or a sign-in waiting for confirmation on account.live.com). Mail treated it as a rejected sign-in; now it recognises it and tries other addresses from the sign-in, a new token with only Outlook permissions, the `/consumers` endpoint for personal accounts, the backup server `imap-mail.outlook.com` and one more attempt after a pause, and remembers what worked. If nothing helps, the window explains what to do (turn on "Let devices and apps use IMAP" in Outlook.com Settings › Mail › Forwarding and IMAP, or confirm the sign-in at account.live.com/activity) and Mail does not keep retrying (**Try Again** button). New command `luxos-mail --diagnose-oauth address` (with `--fresh` for a new browser sign-in) tries all variants and prints a report without ever showing tokens. Covered by tests with fake Microsoft and IMAP servers that fail with the same error the user saw before the fix.
- **Mail: the new-mail notification stays until you close it and appears in Notifications (the bell in the top bar)**: the "New mail from …" notification disappeared after 6 seconds and was not saved in the notification history. Now it is persistent, kept in the history with Mail's icon and name, and further new messages replace it with one "New messages: N" summary instead of a pile of notifications (the history entry is updated too). When all announced messages are read – in Mail or elsewhere – or deleted, Mail closes the notification and marks the history entry as read, even if Do Not Disturb hid the popup. A notification you closed is not replaced any more. Tested with the real notification service and top bar in a virtual screen.
- **Mail: adding Gmail (and other big providers) and showing the password**: adding a Gmail account failed because Google rejects the normal account password over IMAP (only an **app password** with two-step verification works), and Mail only said "E-mail address or password is incorrect"; Gmail's `[ALERT]` explanation got lost. Mail now recognises Google (including Workspace on your own domain by MX), Microsoft, Yahoo, AOL, iCloud, Seznam, Centrum/Atlas/Volný and GMX/WEB.DE and tells you **before signing in** which password to use – for Google with a **Create App Password** button, for Microsoft that password sign-in no longer works (the password is then not sent at all). Sign-in errors show the real reason from the server along with provider-specific advice. Every password field has an **eye button** to show the password (Tab + Space, labelled "Show password"). Gmail folders are mapped by SPECIAL-USE (Sent, Drafts, Trash, Spam); "All Mail", "Starred" and "Important" are under **More** and not synced in the background. Also fixed: the server settings fields stayed hidden after the server was found (so **Set Up Manually** did not work), the window stays centred so its buttons do not slide off screen, a changed address restarts the search and **F10** opens the menu. Tested with fake Gmail and Microsoft IMAP servers and in a virtual screen. Real "Sign in with Google" needs a registered OAuth client and is not available yet.
- **Mail: messages from Dovecot servers without subject and sender**: while new messages were being fetched, Dovecot also sends unsolicited flag updates, which Mail turned into a second, empty row that overwrote the downloaded message – the list then showed messages without subject, sender and date. Responses for the same message are now merged. Found by testing against a real Dovecot 2.4, with a new test for this behaviour.

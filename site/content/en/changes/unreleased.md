- **LuxOS starts with Secure Boot on – nothing to turn off on an ordinary Windows computer** (new `luxos-secureboot` 1.0.0-1, `luxos-care` 16, `luxos-installer` 36, `luxos-i18n` 68, `luxos-docs` 54, ISO, kernel `linux-luxos` signed with the LuxOS key): until now firmware with Secure Boot on refused the ISO and the installed system ("Access Denied") and the only advice was to turn Secure Boot off – not acceptable for people coming from Windows and for companies (and BitLocker then asks for its recovery key). LuxOS now starts through a **Microsoft-signed shim** (the same file as Fedora, signed with Microsoft UEFI CA 2011 and 2023 – older and new computers), which starts the systemd-boot menu and the kernel signed with the **LuxOS key**. The key is added to the computer once, on the first start from the USB stick: blue shim screen → OK → any key → MokManager **Enroll key from disk** → disk → `LUXOS_ENROLL_THIS_KEY.cer` (right at the top) → Continue → Yes → Reboot (11 keys, no typing); the installed system then starts directly. If the USB stick was started with Secure Boot off, the installer prepares the key itself and shows a one-time 8-digit password – on the first start just Enroll MOK → Continue → Yes → password (`SECUREBOOT_ENROLL=auto|yes|no`). Existing installs get shim with an update: `EFI/LuxOS` (shim, MokManager, signed systemd-boot) is added to the EFI partition, the "LuxOS" boot entry goes first and the old one stays as a backup until LuxOS has started once through shim; without Secure Boot nothing changes. To turn Secure Boot on afterwards: `sudo luxos-secureboot enroll` (MokManager waits 60 s instead of 10 s), state: `luxos-secureboot status`. DKMS drivers (NVIDIA, Broadcom) load with Secure Boot without any extra step; `enroll` also adds the computer's DKMS key. System snapshots start with Secure Boot too (the kernel is signed in the package); older snapshots and the previous kernel from before signing show "- needs Secure Boot off" in the menu and LuxOS Recovery then starts with the signed kernel. Only the maintainer has the private key (the Safe); CI builds unsigned packages and signing happens before publishing (`scripts/sb-sign.sh`; `publish-repo.sh` refuses an unsigned kernel). Tested in QEMU with OVMF and Microsoft keys (test key): ISO 1.0.1 refused; new ISO → key enrollment → live system with Secure Boot; installation and start with Secure Boot; snapshot start; out-of-tree module unsigned and signed with a DKMS key in MOK; a 1.0.1 install upgraded with the packages starts without Secure Boot through shim and, after enrolling, with Secure Boot on; firmware with only CA 2011 accepts shim, without the third-party CA (Secured-core) it refuses it – explained in the manual. Guide with screenshots: the **Secure Boot** manual page and *Secure Boot: first start* on the website; plan for LuxOS's own Microsoft-signed shim (no MokManager step): `docs/proposals/secure-boot.md`. Also fixed along the way: `sbverify --cert` reports "OK" even for foreign chains (Microsoft's shim) – the check now requires the LuxOS certificate in the signature.
- **Mail: write, reply, forward and send mail – and messages that look like messages** (`luxos-mail` 1.0.0-9, `luxos-i18n` 67, `luxos-docs` 52): Mail now sends mail (SMTP), not only reads it. **New Message** (Ctrl+N), **Reply** (Ctrl+R), **Reply All** (Ctrl+Shift+R) and **Forward** (Ctrl+Shift+F, with the original attachments) open a message window with From (account picker), To/Cc/Bcc with address suggestions (people you wrote to and senders in your local mail), subject, text and attachments (button, Ctrl+Shift+A or drag and drop; list with size and ×, a warning above 25 MB). Send with the button or Ctrl+Enter; replies quote the original ("On … wrote:" with `>`), keep the thread and mark the original as answered (forwarded) on the server. A signature per account, `mailto:` links with subject and body. **A written message is never lost**: it is saved on the computer 1.5 s after every change (after a crash the window comes back), to Drafts on the server after 30 s (replaced by each new version, removed after sending); closing asks "Save this message as a draft?". Without a connection the message waits in the **Outbox** and is sent automatically (30 s, 1 min … at most every 15 min, at once when the network is back); permanent errors (refused recipient, sign-in, message too large) say exactly why and nothing is sent, an Outbox message stays "Not sent" with the reason and a notification. A copy goes to Sent on the server – except for Gmail and Microsoft, which save it themselves. Own SMTP client in LSL: implicit TLS 465 and STARTTLS 587 with certificate and SNI checks, AUTH PLAIN/LOGIN, XOAUTH2/OAUTHBEARER with Google, Microsoft and LuxAI tokens, SIZE checked before sending; RFC 5322 messages in UTF-8 (RFC 2047 headers, quoted-printable/base64, RFC 2231 file names, no Bcc header). **Received mail is shown properly** (links were not clickable and formatting was poor): messages are shown in a locked-down WebKitGTK (already part of LuxOS) – HTML mail with its layout, colours, tables and attached pictures (on white paper also in dark mode when it has its own colours); plain text with clickable links, quotes as indented blocks with a coloured bar, a dimmed signature and ASCII tables in monospace. Links open in your browser (mailto: in a new message) and show their real address on hover. Remote images and tracking pixels stay blocked until **Load Images** or **Always from <sender>**; scripts, event handlers, forms, iframes, external styles and dangerous links are removed and the message page forbids network access (Content-Security-Policy), JavaScript off, no cookies. Attachments: Open / Save As…, picture previews under the text; Ctrl+F finds in the message, Ctrl+P prints, Ctrl+plus/minus/0 zooms. Ctrl+R is now Reply (like Mail on macOS); get mail with F5 or Ctrl+Shift+N. Also fixed: after a background sync rebuilt the message list, the list lost the keyboard focus and the arrow keys did nothing.

- **A full EFI partition no longer breaks booting: smaller initramfs, guarded space and no empty boot loaders** (`luxos-secureboot` 1.0.0-3 – after the CI build the maintainer must sign it with `scripts/sb-sign.sh package`, `luxos-care` 17, `luxos-tweaks` 13, `luxos-branding` 28, `luxos-installer` 38, `luxos-i18n` 70, `luxos-docs` 56): a real case – the owner's 1 GB EFI partition (`/boot`) was 100 % full. On its first install `luxos-secureboot sync` hit "No space left on device", still printed "Secure Boot loader updated" and left **empty (0-byte) `shimx64.efi`, `grubx64.efi`, `BOOTX64.EFI` and `mmx64.efi`** – the boot entry and BootNext pointed at an empty shim and only the firmware falling back to the old entry saved the boot (that is why MokManager never appeared); a truncated `initramfs-linux-luxos-prev.img.new` (65 MB) was left too. Cause: `set -e` does not apply in `put … && changed=1`, so after `cp` failed, `mv` replaced the file with the empty copy. Every write to the ESP now checks the free space first (for the whole set – nothing rather than half), writes a temporary file, syncs it, compares size and content with the package and only then renames it atomically; on any error the old file stays, nothing empty or partial is left and the error is clear (exit code ≠ 0). BootNext and the first place in the boot order are never set to an entry whose shim or systemd-boot is missing, empty or not an EFI file (`MZ` header) – a damaged one is moved to the end instead. Empty and partial leftovers of its own writes are recognized and repaired, foreign loaders are kept; `luxos-secureboot status` reports `loader=broken` with `loader_damaged=`, `check` gives the reason. **Initramfs 172 MB → 59 MB**: the kms hook added the nouveau driver (blacklisted by the NVIDIA driver, never loaded) with the firmware of every NVIDIA GPU generation (~110 MB, already compressed) – the new initramfs hook `luxos-slim` leaves blacklisted modules that are not loaded out of autodetection; the Plymouth theme uses Inter Variable and Noto Sans Mono instead of the whole Inter.ttc collection and JetBrains Mono Nerd (−6 MB in every kernel copy). On a full partition `luxos-slim` stops mkinitcpio before it would overwrite a working initramfs with a truncated one (with little free space mkinitcpio writes straight into the old image). **Guarded space**: snapshot kernel sets with the same kernel are merged (at most 2 variants, no snapshot loses its entry), before every transaction 100 MB plus room for one more kernel set stay free, otherwise the kernel sets of the oldest snapshots are removed (never the newest one or the snapshot the system runs from; the main and previous kernels are not sets); `lux rollback` also works to a snapshot without a set when the kernel version is the same. After every transaction (`96-luxos-care-esp-check`) `*.new`/`*.tmp` leftovers are removed and the initramfs is checked to be fully readable – a truncated one is rebuilt after freeing space, otherwise a loud error. The check after boot cleans the safe items itself and calmly reports an almost full partition (< 50 MB), a damaged initramfs or boot loader (carefree mode repairs them). New `sudo luxos-care esp-clean`. The installer warns about an EFI partition smaller than 1 GB (new ones get 1 GiB). Also fixed: the previous kernel counted its old files as free space (the new copy is written next to them), a partial snapshot kernel set and `*.luxos-new` stayed on the partition after a failed copy, `luxos-esp-sync` (ESP shared with Windows) could leave a new kernel with the old initramfs.
- **Secure Boot: the blue key enrollment screen appears even on computers that reorder the boot entries their own way (Acer, HP, Lenovo)** (`luxos-secureboot` 1.0.0-2, `luxos-installer` 37, `luxos-i18n` 69, `luxos-docs` 55): a real case – on an Acer laptop (Insyde firmware) MokManager never appeared after `sudo luxos-secureboot enroll` and a restart. The installer prefers the shim entry over an old direct systemd-boot entry on a shared EFI partition and secures the first start of the installed system with BootNext. Also fixed: a direct start of `EFI/BOOT/grubx64.efi` (Linpus lite) counted as a start through shim (`status` said `boot_path=shim`, the service removed the old entry), `status` without root said `loader=missing` and `kernel=unsigned` (only root can read the EFI partition – now the state from the service in `/run/luxos-secureboot/status`, otherwise `unknown`), after a start without shim `luxos_key=missing` even for an enrolled key (MokListRT exists only after shim – now `unknown`), a foreign `EFI/BOOT/grubx64.efi` was overwritten with systemd-boot. VM test (OVMF, Microsoft keys): the exact Acer state → before: "Linpus lite" started, no MokManager; now MokManager through BootNext even with "Linpus lite" first; after the entries were reset, start with Secure Boot on through the fallback.

- **LuxAI: rich answers after the first real tests** (`luxai` 2.0.2-5, `luxos-docs` 48): a quiz whose JSON was on the same line as ```` ```quiz ```` (Flash wrote it that way) showed "This block could not be shown" – such blocks, a closing fence stuck to the JSON, `~~~`, smart quotes and a missing closing fence now work, and the prompt no longer shows one-line examples; inline math with doubled backslashes no longer turns into "vecv" / "sqrt" and unknown commands keep their backslash; SVG text uses the system font and follows the theme, simple `<style>` rules are applied; new exact chart modes "function" (graphs of formulas with labelled points) and "plane" (points, vectors, segments, circles on equal axes) replace hand-drawn SVG graphs whose points missed the line.
- **The Dock no longer freezes halfway through magnifying icons and no longer crashes on a warning** (`plank` 0.11.89-6.1 in `[luxos]`, until now Plank from Arch): occasionally the Dock froze with a half-magnified icon after it was revealed and the mouse moved over it. Plank draws its animations with the GTK frame clock, but it never removed its "tick" and called `end_updating()` on the clock without its own `begin_updating()` (an unbalanced counter); when frames stopped arriving during a running animation, every further redraw request was dropped and the Dock stayed frozen until something else redrew it. Now the tick is registered only during an animation (GTK balances the counter itself), and an **animation watchdog** restarts an animation that got no frame for 1 s, so revealing and magnifying jump to the state they should be in (with a simulated clock stop the Dock without the watchdog stays frozen and magnified, with it it recovers in about 1.0 s). While the mouse is over the Dock its position is also checked every 500 ms, so a lost "mouse left" event no longer leaves the Dock magnified and shown. Intermediate icon sizes while magnifying (48–72 px) are scaled from the full-size icon instead of rendering every size from SVG in the main loop (longest main-loop stall on the first magnification 9.4 → 4.9 ms, after an icon theme change 8.3 → 1.4 ms). Two crashes are fixed too: a GLib warning with a newline and invalid UTF-8 crashed Plank (`SIGABRT` in `string_replace` – `luxos-dock` restarted it after 1 s; this was also the crash "when switching light/dark mode"), and a `.dockitem` file with a name in invalid UTF-8 (`SIGSEGV` when saving the icon list). Tests in `packages/plank/tests` (isolated Xvfb + xfwm4 session with compositing, own HOME/XDG/D-Bus): a stress test of reveal/hover/leave with random timing (fixed Plank: 3500 cycles – 1500 of them while opening and closing windows, adding and removing icons and with tooltips – 700 magnification checks, 400 hides, 0 failures and no false watchdog triggers; the original Plank also survived 2000+ cycles, so the rare freeze is not triggered naturally in Xvfb and is verified by simulation), the watchdog, Logger/UTF-8 and main-loop responsiveness.
- **Mail: signing in with a Microsoft account (Outlook.com) ended with "User is authenticated but not connected"**: the browser sign-in and consent worked, but adding the account failed. Microsoft sends this when it accepts the token but does not open the mailbox (an alias instead of the main address, a token for the wrong resource, IMAP turned off for the Outlook.com account, or a sign-in waiting for confirmation on account.live.com). Mail treated it as a rejected sign-in; now it recognises it and tries other addresses from the sign-in, a new token with only Outlook permissions, the `/consumers` endpoint for personal accounts, the backup server `imap-mail.outlook.com` and one more attempt after a pause, and remembers what worked. If nothing helps, the window explains what to do (turn on "Let devices and apps use IMAP" in Outlook.com Settings › Mail › Forwarding and IMAP, or confirm the sign-in at account.live.com/activity) and Mail does not keep retrying (**Try Again** button). New command `luxos-mail --diagnose-oauth address` (with `--fresh` for a new browser sign-in) tries all variants and prints a report without ever showing tokens. Covered by tests with fake Microsoft and IMAP servers that fail with the same error the user saw before the fix.
- **Mail: the new-mail notification stays until you close it and appears in Notifications (the bell in the top bar)**: the "New mail from …" notification disappeared after 6 seconds and was not saved in the notification history. Now it is persistent, kept in the history with Mail's icon and name, and further new messages replace it with one "New messages: N" summary instead of a pile of notifications (the history entry is updated too). When all announced messages are read – in Mail or elsewhere – or deleted, Mail closes the notification and marks the history entry as read, even if Do Not Disturb hid the popup. A notification you closed is not replaced any more. Tested with the real notification service and top bar in a virtual screen.
- **Mail: adding Gmail (and other big providers) and showing the password**: adding a Gmail account failed because Google rejects the normal account password over IMAP (only an **app password** with two-step verification works), and Mail only said "E-mail address or password is incorrect"; Gmail's `[ALERT]` explanation got lost. Mail now recognises Google (including Workspace on your own domain by MX), Microsoft, Yahoo, AOL, iCloud, Seznam, Centrum/Atlas/Volný and GMX/WEB.DE and tells you **before signing in** which password to use – for Google with a **Create App Password** button, for Microsoft that password sign-in no longer works (the password is then not sent at all). Sign-in errors show the real reason from the server along with provider-specific advice. Every password field has an **eye button** to show the password (Tab + Space, labelled "Show password"). Gmail folders are mapped by SPECIAL-USE (Sent, Drafts, Trash, Spam); "All Mail", "Starred" and "Important" are under **More** and not synced in the background. Also fixed: the server settings fields stayed hidden after the server was found (so **Set Up Manually** did not work), the window stays centred so its buttons do not slide off screen, a changed address restarts the search and **F10** opens the menu. Tested with fake Gmail and Microsoft IMAP servers and in a virtual screen. Real "Sign in with Google" needs a registered OAuth client and is not available yet.
- **Mail: messages from Dovecot servers without subject and sender**: while new messages were being fetched, Dovecot also sends unsolicited flag updates, which Mail turned into a second, empty row that overwrote the downloaded message – the list then showed messages without subject, sender and date. Responses for the same message are now merged. Found by testing against a real Dovecot 2.4, with a new test for this behaviour.

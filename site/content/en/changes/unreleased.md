## Coming soon

So far only in the staging test channel (`channel = "staging"` in `/etc/lux/lux.conf`).

### New
- **Mail: ready for Google app verification**: before you sign in with Google (or Microsoft), the Add Account window explains what Mail uses the access for – only to download, show and organise mail on this computer; neither your mail nor your sign-in is ever sent to LuxOS or anyone else – with a **Privacy Policy** button (luxos.lux-ai.cz/privacy). **Removing a Google account now also revokes Mail's access at Google** (token revocation, RFC 7009 – Mail disappears from myaccount.google.com/permissions); offline, the account is still removed from the computer. The remove confirmation for provider sign-ins no longer talks about a "password". The website has new pages LuxOS Mail (`/mail/`), Privacy Policy (`/privacy/`, with a section on Google user data) and Terms of Use (`/terms/`) in English and Czech, linked from the footer and checked by `scripts/check-site.py`. The verification steps for the project owner, a 120×120 logo and demo video scripts are in `docs/google-verification/`.
- **Mail: "Sign in with Google / Microsoft" instead of an app password**: adding Gmail with an app password is too complicated for most people and Outlook.com does not accept passwords for IMAP at all. Mail now signs in with the provider like Thunderbird (OAuth 2.0 for native apps, RFC 8252): for a recognised provider the Add Account window shows one main **Sign in with Google** / **Sign in with Microsoft** button (neutral text, no logos) and the password field disappears (for Google it stays under **Use an app password instead**). Google Workspace and Microsoft 365 on your own domain are detected by MX. The sign-in opens your browser, Mail listens only on `127.0.0.1` with PKCE and a random `state`, the refresh token is stored only in the keyring and the access token is kept only in memory and renewed automatically. The browser shows a small "You are signed in – back to Mail" page in the LuxOS look and the Mail window comes back to the front. When the provider stops accepting the sign-in (password change, revoked access), a calm yellow bar offers **Sign in again…** and Mail does not retry on its own. Providers are data in `/usr/share/luxos-mail/oauth-providers.json` (administrators can override them in `/etc/luxos/mail-oauth.json`; Yahoo/AOL are prepared but off). **The client IDs are still empty** – until the apps are registered with Google and Microsoft the app-password help stays; the IDs can later arrive without a new package from `https://luxos.lux-ai.cz/mail-oauth.json` (only public client IDs, never endpoints; `{"remote": false}` turns this off). Sending (SMTP) is not in Mail yet, but the sending permissions are requested already. Covered by tests with fake Google, Microsoft and IMAP servers, including a check that no tokens end up in files or logs.
- **Mail: sign in with your LuxAI account – LuxAI mailboxes without a password**: when a LuxAI account is signed in on LuxOS, the first Mail screen offers **Continue as <name>**. Mail asks the LuxAI server which mailboxes the account may use (e.g. `info@lux-ai.cz`) and adds one with a single click – no password and nothing in the keyring: before every connection the background service gets a short-lived token (15 minutes, bound to the account, this computer and the mailbox) and signs in with SASL OAUTHBEARER or XOAUTH2; the account session token goes only to the LuxAI server, never into arguments, Mail files or logs. If the account has no LuxAI mailbox, the normal add-account screen opens with the e-mail prefilled, as does **Use another account…**. Signing out of LuxAI, changing the password or removing access on the server stops new sign-ins at once; an expired sign-in shows **Sign in…**. New menu item **Add LuxAI Mailbox…**. The server side (`server/mail-oauth`: token API, Dovecot 2.4 with OAuth2 and public IMAPS, Postfix submission, fail2ban filters, deploy and rollback scripts) is tested locally and not deployed yet.
- **Mail – LuxOS's own lightweight mail client with instant new-mail notifications** (new `luxos-mail` package in `[luxos-apps]`; phase 1: reading and notifications): a small background program `luxos-mail-service` (no GTK, about 17 MB, starts with the session) keeps one connection per account and thanks to **IMAP IDLE** the server announces new mail itself – a **"New mail from …"** notification with subject and preview arrives within a second, **Open** opens Mail right at the message, several messages give one summary, already read or announced messages stay quiet and Do Not Disturb is respected. Without IDLE it checks every 5 minutes and reconnects right after the network returns or the computer wakes up. The unread count shows on the Dock icon. **The window** has three columns like Mail on macOS (mailboxes, message list with unread dots and attachment clips, message), light and dark, opens in 0.2 s even with a thousand messages, works offline from a local cache and is fully keyboard-controlled (arrows, Enter, Delete to Trash, Ctrl+Shift+U read/unread, Ctrl+F filter, Ctrl+R fetch). **Adding an account** needs only an e-mail address and password: server settings are found automatically like in Thunderbird (provider autoconfig, ISPDB, MX, DNS SRV, verified guessing), with manual setup as a fallback. **Security:** TLS always with certificate verification (no "continue anyway"), the password only in the keyring, never in a file; a wrong password is not retried; HTML messages shown as text without scripts, images or remote content (no tracking pixels). IMAP4rev1/rev2 with CONDSTORE and QRESYNC, MIME with Czech, German and Ukrainian character sets, attachments can be saved. Writing, replying and sending come in phase 2; for now Ctrl+N and `mailto:` links offer to copy the address for webmail. Mail is part of the base installation, Thunderbird stays in the Everyday set (existing systems: `lux install luxos-mail`). Written in LSL, with tests against a test IMAP server and a virtual screen; documentation in `mail.md`.

### Fixed
- **Mail: signing in with a Microsoft account (Outlook.com) ended with "User is authenticated but not connected"**: the browser sign-in and consent worked, but adding the account failed. Microsoft sends this when it accepts the token but does not open the mailbox (an alias instead of the main address, a token for the wrong resource, IMAP turned off for the Outlook.com account, or a sign-in waiting for confirmation on account.live.com). Mail treated it as a rejected sign-in; now it recognises it and tries other addresses from the sign-in, a new token with only Outlook permissions, the `/consumers` endpoint for personal accounts, the backup server `imap-mail.outlook.com` and one more attempt after a pause, and remembers what worked. If nothing helps, the window explains what to do (turn on "Let devices and apps use IMAP" in Outlook.com Settings › Mail › Forwarding and IMAP, or confirm the sign-in at account.live.com/activity) and Mail does not keep retrying (**Try Again** button). New command `luxos-mail --diagnose-oauth address` (with `--fresh` for a new browser sign-in) tries all variants and prints a report without ever showing tokens. Covered by tests with fake Microsoft and IMAP servers that fail with the same error the user saw before the fix.
- **Mail: the new-mail notification stays until you close it and appears in Notifications (the bell in the top bar)**: the "New mail from …" notification disappeared after 6 seconds and was not saved in the notification history. Now it is persistent, kept in the history with Mail's icon and name, and further new messages replace it with one "New messages: N" summary instead of a pile of notifications (the history entry is updated too). When all announced messages are read – in Mail or elsewhere – or deleted, Mail closes the notification and marks the history entry as read, even if Do Not Disturb hid the popup. A notification you closed is not replaced any more. Tested with the real notification service and top bar in a virtual screen.
- **Mail: adding Gmail (and other big providers) and showing the password**: adding a Gmail account failed because Google rejects the normal account password over IMAP (only an **app password** with two-step verification works), and Mail only said "E-mail address or password is incorrect"; Gmail's `[ALERT]` explanation got lost. Mail now recognises Google (including Workspace on your own domain by MX), Microsoft, Yahoo, AOL, iCloud, Seznam, Centrum/Atlas/Volný and GMX/WEB.DE and tells you **before signing in** which password to use – for Google with a **Create App Password** button, for Microsoft that password sign-in no longer works (the password is then not sent at all). Sign-in errors show the real reason from the server along with provider-specific advice. Every password field has an **eye button** to show the password (Tab + Space, labelled "Show password"). Gmail folders are mapped by SPECIAL-USE (Sent, Drafts, Trash, Spam); "All Mail", "Starred" and "Important" are under **More** and not synced in the background. Also fixed: the server settings fields stayed hidden after the server was found (so **Set Up Manually** did not work), the window stays centred so its buttons do not slide off screen, a changed address restarts the search and **F10** opens the menu. Tested with fake Gmail and Microsoft IMAP servers and in a virtual screen. Real "Sign in with Google" needs a registered OAuth client and is not available yet.
- **Mail: messages from Dovecot servers without subject and sender**: while new messages were being fetched, Dovecot also sends unsolicited flag updates, which Mail turned into a second, empty row that overwrote the downloaded message – the list then showed messages without subject, sender and date. Responses for the same message are now merged. Found by testing against a real Dovecot 2.4, with a new test for this behaviour.

## 1.0.0 "Sirius" – 2026-11-04 (beta)

**Warning: this release is still unstable – expect bugs.** All changes since 0.9.12 are in this section and the next one (the 1.0.0 test release of October 28).

### New
- **Sandboxed apps start like normal apps**: after `lux install pi-coding-agent-bin` (community → sandbox) you can just type `pi` in the terminal – before you got "command not found" and advice that did not even apply to command-line tools. Every program of a sandboxed app gets a small wrapper in `~/.local/share/luxos/sandbox/bin`, which is always **last** in `PATH`, so a system program of the same name (e.g. after `lux install --system pi`) always wins. Apps with a window appear right away in Launchpad and the menu as "App (Sandbox)" with their own icon and run in their own Xephyr window. Launchers are kept in sync after install, removal, reset or deletion of the sandbox, at every login and after `lux update` – apps installed earlier get them too, and if a wrapper is missing, the "command not found" handler creates it. After installing, `lux` tells you how to start the app and, for tools, how to install it into the system to use it with your files; `lux remove` removes a sandboxed app from the sandbox. Security: sandbox data is untrusted – package databases, `.desktop` files and icons are read safely with size limits, `Exec` and other keys are never taken over (only a cleaned name, description and category), icons only as plain PNG/SVG, and no wrappers are made for names the system has or for `sudo`, `su`, `pkexec`, `passwd`, `ssh`, `gpg`, `lux` and similar. Launchers use `--net` (internet only; the local network and the computer stay blocked).
- **Performance mode also uses the discrete graphics**: on laptops with hybrid graphics (NVIDIA or a discrete AMD next to the integrated GPU), games and demanding apps run on the discrete GPU in **Performance** mode and on the integrated one in Balanced and Power Saver (battery); the desktop, compositor, top bar and Dock always stay on the integrated GPU. The power profile is the single source of truth: `luxos-hub` follows its changes over D-Bus and runs the new LSL program `luxos-gpu apply`. Native games and apps with `PrefersNonDefaultGPU=true` start through `luxos-gpu run`, which sets the same variables as `prime-run` (NVIDIA) or `DRI_PRIME=1` (AMD). Flathub apps – Steam, Heroic, Lutris, Bottles, Prism Launcher and installed games – get the variables in Flatpak user overrides (only missing keys; LuxOS removes what it added when you leave Performance), so CS2 and other Steam games run on NVIDIA even though Steam itself picks the integrated GPU. If Steam is running when the mode changes, a notification says to restart it. NVIDIA also gets PowerMizer "maximum performance", a discrete AMD GPU the high performance level. Choosing Performance turns off Battery Saver, and the power settings show which graphics card is used for games. `prime-run` still works by hand.
- **LSL 0.10.8**: compiling small and medium programs is 22–33 % faster than with 0.10.7; generated code and modules are unchanged.
- **Maps suggest places as you type**: in the search field and in the route **Start** and **Destination** fields, a list of suggestions appears while you type, like in Apple or Google Maps – first favourite and recent places and stops Maps already knows (ignoring accents and case, "namesti mir" finds "Náměstí Míru"), then places, addresses, streets, towns and stops from **Photon** (`photon.komoot.io`, OpenStreetMap data, no account) sorted by distance from the map centre. Every row has a coloured icon by type, the name with the match highlighted, the street, town, country and distance. ↓/↑ and Enter or a click selects, Esc closes the list, Enter without a selection searches as before. A chosen place goes straight to its coordinates, a route is recalculated at once, and with location permission the first suggestion is **My Location**. Photon is used considerately (query after 250 ms of no typing, only the latest text, at most 7 results, a short cache, a 30 s pause after an error) and the window never waits for the network. Offline, your own places remain. **⋯ › Suggestions While Typing** turns it off, **Clear Recent Places** deletes recent places, `"suggest_url"` sets another Photon server.
- **Fast suggestions in Maps from LuxOS's own geocoder**: suggestions for Czechia and Slovakia now come from LuxOS's own service at `luxos.lux-ai.cz/geocode` instead of public Photon, which took 2.5–3.8 s – towns and districts, streets, house addresses, places (shops, restaurants, sights…) and public transport stops (all platforms of a stop as one row), ignoring accents, nearer places first. The OpenStreetMap data is rebuilt every week. Maps asks after 150 ms of no typing (before 250 ms) and keeps one persistent HTTPS connection. Photon stays as a fallback outside Czechia and Slovakia, when the geocoder does not answer within 1.2 s, or when it finds fewer than 2 matching places. The list footer shows the source ("Suggestions: LuxOS" / "Suggestions: Photon"). Privacy: the server neither stores nor logs queries; rate limiting only keeps an in-memory counter per IP address. New setting `"suggest_providers"` (list of servers in order).
- **`lux search` with aptitude-like patterns**: `^vim` = name starts with vim, `vim$` = ends with vim, `^vim$` = exactly this name, `*qt*` = name contains qt; `*` is any characters and `?` one character (`lib*-git`), and they can be combined (`^python-*qt*`). Patterns search only package names, case-insensitively; a plain word still searches name and description, and several words or patterns must all match. `%` can be used instead of `*` (`lux search %qt%`) so the shell does not expand it – otherwise quote the pattern. Works for the repositories, LuxOS `.lux` apps, Flathub and the AUR. New `lux search --installed` searches only installed packages, `.lux` apps and Flatpaks. Help in `lux search --help`, the man page, bash completion and `package-management.md`.
- **LuxOS Companion 0.4 – model choice, tool progress, approval on the phone and the calendar on the phone**: the computer announces only what the whole chain really supports – calendar reading and LuxAI models, tools and approvals only when the installed LuxAI offers them. The phone can choose the LuxAI model (an unavailable model is an error, never silently another one), sees running tools (name, state, short detail) and can **allow or deny once, on the phone**, actions LuxAI would confirm with a card on the computer – an approval is valid only for the connected phone, the running request and that action, for 60 s and only once; administrator commands and desktop control from the phone never. A new Calendar tab on the phone loads the events of a chosen day in the phone's time zone (all calendars, recurring, overnight, multi-day and all-day events). The **Phone** window has a new **Allow Calendar Reading** switch (on by default) and shows "LuxAI is waiting for your approval on the phone".
- **LuxAI for LuxOS Companion 0.4: models, tool progress and approval on the phone**: `luxai --remote-session` announces models, tools and approvals. The phone gets the same model menu as the app (Flash, Lite) and the chosen model is really used – an unknown model ends with an error, never silently another one. Every real tool call sends its state (running, done, error, waiting for approval) with a short detail; tokens, passwords, `Authorization` headers and the account token are removed. Actions LuxAI would confirm with a card on the computer are no longer denied straight away: the run waits for a **one-time approval on the phone** (60 s, then treated as denied). An approval is bound to the running request, the specific call and a SHA-256 fingerprint of its exact arguments, is valid only once and is invalidated by cancelling or disconnecting; "always allow" is never saved from the phone. Administrator commands, desktop control, sending feedback and dangerous actions are still always refused from the phone with "This action requires confirmation on the computer".
- **"LuxOS wallpapers with an analog clock" screensaver** (Screensaver and Lock › Screensaver): LuxOS wallpapers cross-fade every 30 seconds with a large classic clock in the middle – hour, minute and a smoothly sweeping second hand – and the date below. The dial is light or dark to match the LuxOS appearance. Outside the fade only the clock square is redrawn, the next wallpaper is prepared in the background and nothing is drawn while the monitor is off – about 5 % of one core at 1920×1080; every monitor draws its own.

### Fixed
- **Security: the screen locks as soon as the screensaver starts.** The default "password only after 1 minute" meant that after the screensaver started, pressing Enter let anyone onto the desktop without a password. Now the password is required immediately; running sessions get this right with the update (a delay you chose yourself is kept). Locking on suspend is explicitly on.
- **A fork bomb in the Terminal no longer brings down the whole desktop**: after `:(){ :|:& };:` in the Terminal the whole session stopped working – the top bar showed errors, shortcuts failed and nothing could be started, because the Terminal, top bar, window manager and everything they started shared one process limit for the whole user. Now the Terminal runs as a user systemd service and the shell of **every tab** is in its own scope with a process limit far above `make -j`, browsers, Steam or Electron. A bomb only hits the limit of its own tab; the top bar, Dock, Search, shortcuts and other tabs keep working. A tab that hits the limit prints a red line and sends a "Too many processes" notification, and **closing the tab ends all its processes at once**. Works after `lux update` without logging out or restarting (an already open old Terminal only after all its windows are closed). Verified in a VM with 3 GB RAM: the bomb now stops at 4096 processes in its tab while the session stays untouched.
- **The Bluetooth window no longer grows in memory**: left open for 19.5 hours with headphones connected, it used 1.27 GB of RAM plus 992 MB of swap. Every redraw (BlueZ reports the signal strength of nearby devices several times a second while searching) leaked the device rows because of a reference cycle. Rows are now destroyed, signal-strength and similar updates no longer cause a redraw (about 9× fewer redraws), and after 2 minutes in the background the window stops searching for new devices (searching strains the radio – worse headphone sound, battery). Measured with a fake BlueZ: before 93 → 752 MB in 60 s, now 93 → 96 MB and stable even after 5 minutes. New tests.
- **The volume icon in the top bar no longer freezes**: the volume notification was sent synchronously – when the notification service did not answer, the whole plugin hung for 25 s on every volume change (and at panel start), the icon could not be opened and volume keys did nothing. Now the notification is sent asynchronously with a 1.5 s limit. A menu that GTK could not open, or that a sound server outage hid, no longer blocks the button permanently. A crash when the panel quits is fixed too. Verified with a fake, unresponsive notification server: before 25.1 s of blocking, now 0 ms.
- **Notifications come back by themselves after running out of memory**: the earlyoom guard killed the notification service 5× in 2 s and it then stayed down until started by hand (apps waited 25 s for a timeout). All user services had a higher kill score than a 4 GB game, so earlyoom killed dozens of tiny services without freeing memory. Now the small session services (notifications, Xfce settings, power manager, screen lock, keyring, portals, gvfs, dconf, polkit agent) are protected, Steam's web helper and WebKit are preferred for killing, and a stopped notification service restarts within 2 s. New test.
- **LuxAI in Agent mode really runs a tool call the model wrote as text**: the Flash model sometimes sent a tool call as text instead of through the tool-call channel (typically when writing a large file did not fit into the response limit), and LuxAI showed it as a Markdown answer and did nothing. Now a complete call of an offered tool in the GLM, Hermes/Qwen or Qwen3-Coder text format is turned into a normal call and goes **the same way as a native one** – safety rules, approval card, denial; the call text is not shown while the answer is being written. A truncated or invalid call is never run: the model is asked once to write the big file in parts, the second time a clear error is shown. The agent now gets up to 8192 response tokens for tool calls (before 4096). Older saved messages with a written-out call are shown as a code block, unfenced code keeps its indentation, answers loaded from history no longer show "Thinking…", and the **context menu** over your own message is no longer white on white.
- **Canon printers with the UFR II driver (e.g. MF4100 over USB) are added with one click**: the Canon driver has the printer language after the model name ("MF4100 Series UFRII LT") and LuxOS did not recognise it; it now prefers the driver for the language the printer reports (UFR II LT, not CARPS2). An error while adding now gives the real reason (driver missing / cannot be downloaded) instead of "check that it is turned on".
- **Battery graphs show history again even after a day on the charger**: upower records only changes and the new version 1.91 returned nothing for `points=0`; the graph now takes a week of records and the value valid at the start of the 24-hour window.
- **Flathub apps appear in Launchpad and the menu right away**, not only after logging in again: Flatpak folders are always in `XDG_DATA_DIRS`, even when Flatpak is only installed with the first app.
- **Flathub apps appear in Launchpad and the menu right away even in an already running session and for all users**: a new service watches the system-wide Flatpak apps and links their `.desktop` files and icons into `/var/lib/luxos/apps`, which every session has in `XDG_DATA_DIRS` – even one logged in before the update. Works for `lux install`, the Store and plain `flatpak install`/`update`/`uninstall`; removed apps disappear from the menu. `lux` waits (at most 3 s) until the app is in the menu. The same app in two folders is listed only once, and a Launchpad sorted by category re-sorts after an install or removal (a new app is no longer stuck at the end of the grid).
- **The LuxOS logo in the Terminal no longer stays over `top` output**: running `top` right after the welcome logo left the SIXEL image drawn over its output. Images now belong to the cells under them like in xterm: text overwrites them, clearing a line or the screen hides that part, they scroll into history with the text (also after resizing) and are not drawn over the alternate screen (`vim`, `less`, `htop`). Verified with screenshots and a new test.
- **Lux Code no longer flickers and streams answers live again**: the interface sent the whole screen (~9–12 KB) twice a second even with no change and on every key, and the terminal sometimes showed a half-empty frame. Now the frame is composed in memory and only changed lines are sent in one write using synchronized output (DEC 2026); nothing is written while idle, and typing a character sends ~400 B instead of ~9 KB. The terminal size is read with an ioctl, rendered Markdown is cached and Ctrl+L redraws the screen. Background jobs are fixed too: the TUI froze during a model request and the answer appeared all at once – now text streams in, Esc/Ctrl+C cancels the request and background shells and services really run in the background. The model also gets the current local date, weekday, time and time zone, the system name and version and the working folder with every request.
- **Navigation in Maps recalculates the route when you go another way**: public transport was never recalculated (just "You are off the route.") and going back along the route did not count as leaving it. Now the **opposite direction** is detected too and **public transport is planned again** from your current position – when you leave a walking leg, are more than 150 m from the line in a vehicle, or **missed your connection** (not on board 90 s after departure: "You missed your connection. Looking for another one…"). The new connection replaces the old one everywhere while "Arrive by" stays, with at most one search per minute. Walking needs 35 m off the route (bike 40 m, car 50 m); parallel streets, GPS jumps of a standing phone and short glitches are ignored. A new car or bike route starts in your direction of travel. Verified by replaying real phone tracks.
- **The location arrow in navigation moves smoothly** instead of jumping: between fixes its position is predicted from speed and direction (at most 1.5 s), on a route it snaps to the route line, a new fix is blended in within a fraction of a second and the map rotates the shortest way. It draws only while moving – at most 30 frames per second, nothing without new positions.
- **Long public transport connections fit into the Maps panel**: leg badges wrap onto further lines, long line names are shortened with an ellipsis (full name in a tooltip) and the delay sits next to the line name, so a 280–560 px panel never overflows sideways; the Car/Bike/Walk/Transit buttons shorten in a narrow panel.
- **The analog clock screensaver no longer shows leftovers of the password dialog after Esc**: the screensaver redraws only the clock square outside the fade, and the screensaver program left the last frame of the dialog underneath – the date, a large time and the lock wallpaper stayed around the clock. Now the screensaver's own last frame is kept and its whole window is exposed, and LuxOS screensavers redraw the whole screen after every expose, after a pause and at least every 5 s. Verified by screen capture: now the whole screen is the screensaver 25–40 ms after the dialog closes; the other clock styles have no leftovers either.
- **Maps had no icon in Alt+Tab** when the icon theme pointed to a missing file: Maps now uses its installed icon directly in that case.
- **The login spinner turns smoothly** instead of stuttering: even rotation with a constant arc length at 60 frames per second.
- **Login is fast again – the spinner transition delayed the session start by up to 15 s**: every spinner redraw generated an event that woke the loop at once, so the spinner was drawn non-stop, the X server ran at 100 % and the window manager and desktop only started after the cover ended (15 s on a real computer). The spinner now draws without these events, at most 30 frames per second and at lower priority (~1 % of a core); the window manager now starts in 280 ms with or without the transition (before 1,700–2,000 ms). The transition also ends within 3 s if no window manager appears, and always within 10 s (instead of 15 s). LightDM starts X with `-noreset` (like GDM), so the frame left by the login screen no longer disappears. A test now also measures the time to the window manager with a real session.
- **Notifications: the close cross is red and without a white background.**
- **No more black screen after login – the wallpaper with a loading spinner like on macOS**: from accepting the password until the desktop is ready, you see the dimmed login wallpaper with a small spinner where the password field was, and then it fades into the desktop. The causes of the black screen (found by capturing hundreds of frames per second): the compositor often did not draw a full-screen window that existed before it started, the cover ended before the desktop had loaded its wallpaper, and on drivers without glamor (QEMU) the gap between the login screen and the cover was black. Now the cover sits in the compositor overlay window, ends only when the desktop really shows the wallpaper and the top bar and Dock are drawn (at most 15 s), and the login screen leaves its last frame on screen. A new test fails on any black frame – the old version had about 100 black frames in every run, the new one none.
- **Waking the locked screen without a black frame**: after a key press or mouse move, the screen went black for ~0.3 s before the password dialog appeared. The window now keeps the last screensaver frame as background until the dialog is drawn, and the last dialog frame when returning to the screensaver. Verified by screen capture: before ~200 black frames at every wake-up, now none.
- **Battery graph in Battery and Power**: the "0 % / unknown" record upower writes at every boot is no longer drawn as a discharge, and a computer that was off or asleep breaks the line instead of drawing a long slanted one. A value stays valid until the next change and the graph ends with the current state.
- **The phone (LuxOS Companion) now finds the computer – the computer is visible while the Bluetooth settings are open**: LuxOS never made Bluetooth discoverable, so the phone did not see the computer at all, while the Bluetooth window misleadingly said "Other devices see this computer as …". Now, like on macOS, the computer is visible **while the Bluetooth window is open** and Bluetooth is on ("Visible as "jupiter" while this window is open", otherwise "Not visible to other devices"). Closing the window or turning Bluetooth off ends visibility – only if the window turned it on; visibility has a 3-minute limit that the open window renews, so even a crashed window does not leave the computer visible forever. The **Phone** window has a new **Pair Phone…** button: the computer is visible for 3 minutes with a countdown and instructions, ending on pairing, Cancel or closing the window. Pairing alone still allows nothing – LuxOS asks on the first connection as before. The Bluetooth window now also asks for pairing without a code and for services of untrusted devices instead of silently allowing them.
- **LuxAI no longer crashes when you click an old conversation**: clicking a conversation in the sidebar sometimes crashed the app, because opening it rebuilt the conversation list while GTK was still handling the row selection. The conversation now opens after the click has finished; verified by an automated test with real mouse clicks in a virtual screen, which used to crash on the second click.
- **Progress of the last step of `sudo lux update`**: the "Finishing" line (post-install hooks – mkinitcpio, DKMS, icon caches, systemd…) sat at 0 % for a long time and then jumped to 100 %. `lux` now works out which hooks the transaction will run and shows "Finishing ███░░ 25 %  3/12 · Updating linux initcpios", correcting the estimate from the libalpm debug log. Pre-transaction hooks (system protection, snapshot) have their own "Preparing" line. In machine mode there is a new phase `@@PHASE prepare`.
- **The "Maps with navigation and Weather" icon in the What's New window**: there was just a blue square instead of an icon, because the WhiteSur icon theme links that symbolic name to a coloured app icon, which GTK recolours entirely. The window now skips coloured icons under symbolic names and uses the Adwaita icon instead; a new test checks that every What's New icon is really symbolic.
- **The Text Editor has its own LuxOS icon again**: the editor uses the original LuxOS notes icon in the Dock, Launchpad, menu and Tour, and its window icon is scaled down from a 512 px PNG with a quality filter, so it is sharp in Alt+Tab too.
- **Text Editor in the Dock**: new users have it in the Dock (after the Terminal); for existing profiles it is added once if missing, so if you remove it later it does not come back.
- **What's New in the Dock**: while the window was open, the Dock showed the program name "luxos-whats-new" and a blurry icon. The window now has a proper hidden `.desktop` file (translated name in 12 languages) and a sharp 16–256 px icon; a new shared function writes the full icon list including 256 px, used by What's New and Calculator.
- **The Calculator has an opaque title bar**: the window's title bar was fully transparent (the calculator's background gradient showed through); now it is the normal theme bar, light or dark, while the calculator body stays the same. The f(x) button has a subtle background so it is visible in the light appearance too.

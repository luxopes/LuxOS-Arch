## 1.0.3 "Sirius" – 2026-11-19

Release 1.0.3 "Sirius" with a new ISO: hundreds of fixes from a full audit of the whole system, safer backups, safe installation alongside Windows, sandboxed apps can no longer look into other windows, a fixed Calendar and Calculator, Firefox without needless connections to Mozilla, network printers only after you click Add, a new About This Computer window, windows that fit small screens, dates and numbers in your language and a LuxAI that no longer gets stuck in a loop. Installed systems get everything with `lux update`. Mail and the developer tools (App Studio, Icon Studio, LuxOS SDK) stay in the staging test channel for now (their changes are under Coming soon), and Lux Code stays at its previous version in the stable channel.

### New
- **LSL 0.10.14** (`lsl` 0.10.14-1; previously 0.10.9–0.10.13; 0.10.11 speeds up floating-point code, 0.10.12 brings security and correctness fixes: TLS verification without a server name, HTTP server limits, overflow in matrices and range, `in` equality, built-in modules protected; 0.10.13 fixes % and // results for floats and a crash when writing to a reset TLS connection; 0.10.14 fixes `^` with floats): window move and resize via the window manager, screen coordinates, window state (maximized, fullscreen), fast blur and saturation of images (cairo/gdk-pixbuf, 1920×1080 in 0.15 s), bulk pixel access and helpers for transparent rounded windows built into the gtk library.
- **A very bright wallpaper like on macOS: a soft shade under the menu bar and around widgets – and widgets in Desktop & Dock** (`luxos-desktop` 79, `luxos-i18n` 81, `luxos-docs` 74): on an almost white wallpaper (white, beige, a white linen texture) the white text of the menu bar and the widgets was barely visible. Now – like on macOS – the wallpaper under the bar and a little below it darkens with a smooth fade (at most 38 % black at the top, gone after 128 px); it is not a darker bar but a shade under it. The white bar text stays white with at least 4.5 : 1 contrast (WCAG AA) and switches to dark only when even that is not enough. On a bright wallpaper every widget card casts a soft dark shadow, so the light card with dark text stands out from the light desktop. The strength follows the brightness of the wallpaper (computed in advance for each wallpaper – switching workspaces with the slide loads nothing and takes as long as before): ordinary wallpapers including the light Sunrise, Lagoon and all dark ones look exactly as before, and the shade goes away by itself with a normal wallpaper. It follows the wallpaper of the active workspace, in light and dark mode, with HiDPI; it needs the compositor (the default), without it the bar behaves as before. The `luxos-bar` plugin paints the shade into the wallpaper strip of the bar and, below the bar, into its own transparent desktop window (above the wallpaper, below widgets and windows, taking no clicks – right-click on the desktop works there too). Turn it off with **Darken bright wallpaper under the menu bar and widgets** in **Desktop & Dock › Wallpaper** or `luxos-appearance desktop-scrim off` (`DESKTOP_SCRIM=0`). Widget settings no longer need Search: **Desktop & Dock** has a new **Widgets** section with **Show widgets on the desktop** (it also follows changes made in the gallery) and **Edit Widgets…**, and the desktop menu (right-click on an empty desktop) has **Edit Widgets…** under **Desktop Settings…** (GTK module `luxos-desktop-menu` in xfdesktop, not inherited by apps started from it). The transparent edge of a widget window no longer takes clicks – they go to the desktop. Tests: `test_luxos_bar_scrim.py`, `test_luxos_desktop_scrim_gui.py` (the whole desktop under Xvfb with xfwm4, xfdesktop, the bar and widgets), `test_luxos_desktop_menu.py`, extended `test_luxos_widget_glass.py`.
- **LuxAI, Lux Code, LSL IDE and the Organization network are now proprietary – still free on LuxOS** (`luxai`, `lux-code`, `lsl-ide`, `luxos-domain`; `LICENSES/`, build, website): the source code of these four components moved to a private repository and new versions are released under the LuxOS proprietary license (`LICENSES/LicenseRef-LuxOS-Proprietary.md`, third-party components in `LICENSES/NOTICE-proprietary.md`). Nothing changes on LuxOS: they are still installed free of charge as signed packages from the LuxOS repository and are included in the ISO. The rest of LuxOS stays open source under GPL-3.0-or-later (with the additional permission in `LICENSES/LuxOS-GPL-exception.md`); versions published earlier stay under the license they were released with. Building from the public repository (`./build.sh`, GitHub Actions) downloads these packages from the published repository and verifies their signatures; the FAQ and the terms of use describe what is open and what is not.
- **The Organization network (LuxOS AD) is a native LSL program** (`luxos-domain` 1.0.0-4, `luxos-greeter` 1.0.0-12): `lux domain`, the system-change helper and Settings › Organization Network are compiled LSL programs instead of Python – the same commands, files, SSSD/Kerberos settings and behaviour, no Python or PyGObject in the dependencies, the window opens faster. The login screen reads the domain state with `lux-domain status --json` (without the package, with other output or outside a domain it shows no domain line, as before).

- **LuxOS News: messages from the LuxOS team right in the system** (`luxos-desktop` 1.1.0-89, `luxos-i18n` 93, `luxos-docs` 84): the new LuxOS News app (`luxos-news`) shows announcements from the LuxOS team – a new release, planned server maintenance, important changes. New announcements also come as notifications (a click opens the app); the check runs 3 minutes after login and then every 6 hours, downloads only one file, `https://luxos.lux-ai.cz/announcements.json`, and sends nothing. Unread announcements are on top, important ones have an orange label and their notification stays until closed. On the first run older announcements are only shown in the app (no avalanche of notifications), at most 3 notifications per check; the **Notify me about news** switch turns them off. Every feed entry is checked (id, dates, text lengths, `https://` links only), a feed over 256 kB or with another version is dropped and no text is ever interpreted as markup. The window matches the other LuxOS apps, in 12 languages. For developers: `luxos-news new` and `luxos-news validate` (`docs/developers/announcements.md`); the website publishes the feed `site/announcements.json` (empty for now). Tests: `test_luxos_news.py`, `test_luxos_hub_lsl.py`.
- **LuxAI Account: credits instead of token limits – one bar "X of 20,000 credits this month"** (`luxos-account` 1.0.0-12, `luxos-i18n` 95, `luxos-docs` 87): since 19 November 2026 every LuxAI account has **20,000 credits per month shared by all models** and all apps (LuxAI, Lux Code, LSL IDE) instead of monthly token limits per model (Flash 1,000,000, Lite 10,000,000); a request costs credits according to its real price. The Overview in the LuxAI Account app now shows one bar with the percentage and "12,345 of 20,000 credits this month" – the numbers always come from the server (`usage.credits` / `usage.creditsLimit` from `GET /api/me`), with the thousands separator of the app language (new `luxos_i18n.format_integer`) – and the renewal date when it can be derived from `usage.month`; an unlimited account shows "Unlimited". When the credits are used up (HTTP 429 `{"error": "monthly_limit", "unit": "credits"}`) the message is "You've used this month's LuxAI credits. They renew on <date>." (without the date when it is unknown); `luxai_account.error_text()` returns the same message for apps and a limit 429 is no longer retried. An older server that sends only tokens (`fastTokens`/`fastLimit`/`liteTokens`/`liteLimit`) still gets the old Flash and Lite bars. New strings in all 12 languages (the unused "%s: %s of %s tokens" removed); Help (LuxAI account, Lux Code, Troubleshooting), the Store description, the README and the website (FAQ, Lux Code) talk about credits. Tests: `test_luxai_account.py` (new and old `/api/me` shapes, `usage.month`, the `monthly_limit` error from a fake server), `gui-account.py` (Xvfb, fake server: credits bar, custom limit, used up with and without a date, unlimited, old server, cs/en).
### Fixed
- **The LuxAI check of community packages said "looks suspicious" even for safe packages** (`lux` 0.3.0-32): the Flash model (now Claude Haiku 5.5) always thinks first and had no room left for the answer, so the check couldn't be confirmed. It now has enough room for both.
- **Terminal: text typed right after opening a window no longer also appears in the top-left corner** (`luxos-shell` 1.1.0-21): what you type during the welcome screen is shown once, at the prompt.
- **Software Update: the history shows exactly what was updated** (`luxos-care` 1.0.0-27, `luxos-desktop` 1.1.0-90, `luxos-i18n` 94): clicking the "LuxOS was updated" notification opened the Software Update window, but the "Updated 34 packages · just now" row in Repair and update history could not be opened – there was no way to see what had changed. Now every update and repair row expands: the packages sorted by name with old → new version (installed, removed, back to an older version), apps also with their name; a long list scrolls. When `luxos-branding` changed there is also a LuxOS release notes button (What's New). A repair shows the problem, what LuxOS did, its output and the reinstalled packages. LuxOS Care records the list of changes with every update and repair (from the package manager log `/var/log/lux.log`); for older updates it looks them up in that log (read-only) at the time of the update, and if nothing is found it says "Details aren't available for this older update." The Details button of the notification after an update (and after a repair) opens the window with the newest entry already expanded. The history also keeps its size in check and only the package count goes to the log. Tests `test_luxos_care.py` (recording the list, lux.log window, old entry without data) and `test_update_history_gui.py` (Xvfb).
- **A network printer out of reach no longer shows a green "Ready"** (`luxos-printing` 1.0.0-21, `luxos-docs` 85): a printer added on another network (e.g. a Kyocera via IPP Everywhere) stayed "Ready" in Printers & Scanners for hours after leaving that network, even with the app open the whole time. CUPS reports a driverless queue as ready until a print job fails, and avahi keeps the printer's announcement cached for a while. Availability now comes from what is visible on the network right now: the printer's announcement (mDNS) and a short connection to its address (`ipp://`, `ipps://` and `socket://` queues by the address and port in the URI), always off the app's main thread and with a short timeout. An unreachable printer shows "Not connected" (with the number of waiting documents), just like an unplugged USB printer; a reachable one stays "Ready". The status refreshes every 12 s while the window is open and right after a network change. Queues and CUPS settings are not changed. Test `test_luxos_printing_reachability.py` (simulated avahi and connection check, window under Xvfb).
- **LuxAI: an answer that starts repeating itself is stopped** (`luxai` 2.0.2-13): when the model keeps writing the same passage over and over (4 or more times in a row; code, tables and numbered lists don't count), LuxAI stops the answer and retries it once by itself with a higher `frequency_penalty` – the looped beginning disappears from the window and the history. Only if the retry loops too is the answer trimmed to one occurrence, and the window (and the LuxOS Companion remote session) shows "The answer started repeating itself and was stopped." (12 languages). A looped answer never runs a tool and the agent does not continue with it. Requests carry `frequency_penalty` 0.3 (dropped if the server rejects it). Built with `lsl` 0.10.14.
- **The lock screen has Sleep, Restart and Shut Down again after waking from sleep** (`xfce4-screensaver` 4.20.2-1.8): right after waking up, the power buttons at the bottom of the lock screen were missing. Whether to show them was decided only once, when the dialog was created, which happens exactly while the computer is waking up and logind and polkit are not keeping up yet (the query timed out or did not return "yes") – the buttons then stayed missing until the next lock. Now the state is checked again without blocking the screen: when the dialog appears, when the login part slides in, after waking up (the PrepareForSleep signal) and then a few times a second apart. A button that would need an administrator password (e.g. another user is signed in) stays hidden. Test `tests/gui-power-buttons.py` (Xvfb, simulated logind on its own bus).
- **Installer: fixes from the final audit before the stable release** (`luxos-installer` 1.1.0-46, `luxos-i18n` 89, `luxos-docs` 81, `luxos-desktop` 1.1.0-86): manual mode (partitions mounted in /mnt) with a root that is not a btrfs subvolume (ext4, xfs) no longer fails after the packages are downloaded; a kept existing volume (e.g. ext4 as /data) is mounted with its real file system instead of as btrfs; reinstalling next to other systems makes the new installation the default boot entry (before, the old one stayed and could point to a deleted partition); a Ventoy or dd-written installation USB is no longer offered as the target disk; the suggested user name for “Žofie” is “zofie”, not “ofie”; system account names (e.g. systemd-network) are refused in the text installer and in config files too; one server being down no longer means “no internet”; Esc in a text installer question just cancels (“Cancelled. Nothing was changed.”) instead of reporting a failure; a disk password with a line break (impossible to type at start-up) is refused up front; after a failed installation no gpg-agent is left holding the target disk mounted; the time zone detected from the IP address is used only when it is a known time zone; the graphical installer reports a missing BIOS boot partition the same way as the installation does (one on another, unused disk is not enough); unused login screen scripts (compositor for the old greeter) removed; docs: /tmp is encrypted only with disk encryption, and the time-zone lookup (ip-api.com) is described in the privacy policy.
- **SFTP network backups work again** (`luxos-backup` 1.0.0-8, `luxos-i18n` 89): after an earlier fix, backup and restore to an `sftp://user@server` address could not connect. Deleting an old backup renames it first, so an interrupted delete (power cut, unplugged disk) no longer leaves a half-deleted backup that looks complete; the rest is cleaned up on the next run. When other files fill the disk, Backups no longer delete every old backup but the last one each hour. The "no backup for X days" reminder is counted per disk, so a forgotten USB disk is reminded even while a NAS keeps backing up.
- **Lux Guard no longer reports "System files were changed" every week** (`luxos-care` 1.0.0-26): the weekly file check took the permissions that the Lux Guard package sets for its session helper for a foreign change, on every computer with Lux Guard. A snapshot before an update that fails (full disk) is now shown as a notification and old snapshots are still cleaned up; manual "Update" works on networks where only the NetworkManager connectivity check fails; Ctrl+C in a terminal during `luxos-care update` no longer stops the installation half-way; a running `lux search` or an idle PackageKit no longer postpones updates.
- **Lux Guard: home snapshots and file restore** (`luxos-guard` 1.0.0-14): when the hourly snapshot does not fit on a full disk, old snapshots are still cleaned up (they hold deleted files); restore with overwrite keeps the current version of a file even across partitions, and two files with the same name from different folders no longer overwrite each other in the backup.
- **Safe: a hand-edited setting no longer turns off auto-lock or blocks unlocking** (`luxos-safe` 1.0.0-12): an empty or invalid idle time means the default 15 minutes.
- **lux: an interrupted installation is no longer reported as success, and more** (`lux` 0.3.0-31, `lux-engine` 7.1.0-3.8, `luxos-sandbox` 1.0.0-13, `luxos-i18n` 89): Ctrl+C or a shutdown during installation used to end with an "updated" message although only some packages were installed; lux now says to finish with `lux update`. Switching the channel (staging to stable) forces fresh package lists. `lux update` also updates community packages installed in the sandbox and no longer looks up LuxOS packages in the AUR. .lux apps are installed in the version just listed by `lux update`. `lux clean` waits for a running update and does not delete its packages. Login, sudo and disk files (PAM, sudoers, sshd_config, fstab) are no longer merged automatically during updates: your file stays and you get a notice. A community build script with a non-UTF-8 character is checked in full instead of being refused. A broken .lux package keeps the old version running. The script diff for community updates is shown against the last built version.
- **lsh: LSL session file only in a private folder** (`lsh` 1.0.0-5): without its own `XDG_RUNTIME_DIR` (for example `sudo -s`) the session file used a predictable name in the shared `/tmp`; it is now always in a private folder.
- **Packages: file ownership and builds** (`luxos-themes` 2025.12.27-12, `luxos-desktop` 1.1.0-86, `luxos-branding` 1.1.0-31, `luxdrop` 1.0.0-11): WhiteSur theme files belong to root (previously to the first user), the `luxos-desktop` build is not stopped by a Python cache in the work tree, and the build number in os-release takes its date from SOURCE_DATE_EPOCH. Driver checks: 8 drivers (Brother, Canon MG7700) got a fixed install script and all drivers are verified again under the new rules.
- **LSL IDE and LuxAI: fixes from the security review** (`lsl-ide` 1.0.0-9, `luxai` 2.0.2-12): LSL IDE cloud files are saved only inside the local cloud folder; the account session is not sent to another server on a redirect; the IDE downloads LSL only with a verified checksum; the model menu no longer shows wrong limits and usage follows the selected model. The LuxAI agent doesn't open files through /proc, and in "risky" mode only truly read-only commands run without asking.
- **Calendar: repeating events in UTC and from Outlook show the right time, an unreadable calendar is never overwritten** (`luxos-desktop` 1.1.0-88, `luxos-i18n` 92): a weekly meeting stored in UTC (Google, Outlook) no longer moves by an hour after a daylight saving change and stays in UTC when saved. Time zones with Windows names (Outlook, Teams, e.g. "W. Europe Standard Time") are recognised through the CLDR table; before, the time was read as local time. BYYEARDAY, BYWEEKNO and hourly rules now work; before, only the first occurrence was shown. When the calendar file exists but cannot be read, Calendar refuses to save and says why. Before, it could overwrite the file with only the new event. The previous content is also kept in `events.ics.bak` before every save. Reminders set more than two days ahead (e.g. a week) now go off.
- **Desktop: small fixes from the audit** (`luxos-desktop` 1.1.0-88, `luxos-i18n` 92): Joining Wi‑Fi from a QR code (Camera) no longer puts the password on the `nmcli` command line, where other users of the computer could see it. It goes through a temporary file only you can read. Network Admin reads the network state correctly in every language (SSID). Pairing a Bluetooth keyboard shows the code in one window that updates while you type. Before, windows piled up on top of each other. The PIN from the device is shown as it is. Calculator: 0, ± and 5 gives −5, not −05. System Monitor no longer counts virtual machine time twice, which made CPU load look too low while a VM ran. Battery & Power shows both batteries on laptops that have two, and no longer shows an empty battery as "Plugged in, not charging". Feedback also removes IPv6 addresses and Wi‑Fi network names from the logs. A report is no longer dropped when your sign-in has expired; it is sent after you sign in again. A screen recording is kept even if the app crashes while recording. Before, only a hidden `.part` file was left. Dragging the Sound and Brightness sliders in Control Center no longer starts dozens of processes, and the last value is the one that sticks. Two alarms in the same minute both ring. Critical safety notices (too many processes, low memory) can only be sent by the system, not by another user of the computer. A full or read-only settings folder no longer stops Keep Awake or the widgets. The menu bar loads a large wallpaper only at screen size. Text Editor is also added to an empty Dock.
- **LuxDrop: files sent at the same time, and the PIN** (`luxdrop` 1.0.0-12): Files sent from LocalSend at the same time into one folder no longer fail at random. A finished file used to remove the shared folder for unfinished files while other files still needed it. A file that was saved is no longer reported as failed only because its temporary copy could not be cleaned up. One device with many IPv6 addresses can no longer use up the shared limit for wrong PINs and block PIN transfers for everyone else. Trusted devices never need the PIN. A connection that drops while sending is reported as "connection lost", not "connection failed".
- **Printing: network printers only after you click, Scanner keeps an open session** (`luxos-printing` 1.0.0-20, `luxos-i18n` 92, `luxos-docs` 82): LuxOS no longer adds a printer announced on the network (mDNS, which anyone in a café or hotel can send) by itself or makes it the default. It offers it in a notification with **Add**. USB printers are still set up on their own. A second Scanner window no longer deletes the scanned pages of a window that has been open for more than a day.
- **Firewall: opening a port asks for the administrator password** (`luxos-firewall` 1.0.0-4, `luxos-desktop` 1.1.0-88, `luxos-docs` 82): **Allow** in the blocked-connection notification used to open the port for the local network without a password. It now asks for the administrator password like other firewall changes, and remembers it for a few minutes.
- **Privacy: Firefox, Feedback and the website** (`luxos-desktop` 1.1.0-88, `luxos-docs` 82, website): Firefox no longer asks Mozilla for your country by IP address, and no longer checks your connection and Wi‑Fi sign-in pages through detectportal.firefox.com; LuxOS detects sign-in pages itself. Firefox no longer suggests add-ons or Pocket stories. This matches the welcome page's promise of "no technical data to Mozilla". The privacy policy now says that Maps' My Location sends the Wi‑Fi networks around you to BeaconDB (only after you agree), and that Feedback also removes IPv6 addresses and Wi‑Fi names. The usage page suggested `sudo lux-config set-countme off`, which does not exist; the right command is `lux config countme off`. ISO verification uses `sha256sum -c --ignore-missing SHA256SUMS`. Without it, the check complained about missing files even when the download was fine. The ISO size is shown in decimal GB, like in the installer.
- **The Sandbox window no longer has a trusted link to your desktop (X11)** (`luxos-sandbox` 1.0.0-12, `luxos-i18n` 88, `luxos-docs` 80): apps in the sandbox always saw only their own Xephyr, but Xephyr itself connected to your desktop with your full trust – had an app hijacked it (a Xephyr bug), it could have read keys typed into other windows, taken screenshots and typed into other windows, as X11 allows. Xephyr now runs in its own bwrap (no home, network or session, seccomp) and connects with an **untrusted authorization** from the X server's SECURITY extension, new for every run, kept in memory only (never `~/.Xauthority` or its FamilyWild entry) and revoked when the sandbox exits. Verified under Xvfb (`tests/test_x11_untrusted.py`): XQueryKeymap, selecting another window's events, RECORD, XInput2, XGetImage of a window or the screen, XSendEvent and XTest are refused; the test fails on the old code path. Remaining: the SECURITY extension does not stop `XGrabKeyboard` (an active, visible keyboard takeover). For apps that are too slow without MIT-SHM, the Sandbox window has a per-app **Trusted display** option (with a warning, off by default; `luxos-sandbox trusted-display`). Flatpak apps with the x11 permission still get your trusted cookie (LuxOS does not wrap Flatpak) – documented.
- **`lux fix` no longer leaves a half-updated system and `lux install` no longer installs onto an outdated system** (`lux` 0.3.0-30, `luxos-i18n` 85): `lux fix` refreshed the package lists but installed only the signing keys – a later `lux install` then took packages built against newer libraries than the system had (the program did not start) or upgraded a library that old programs need. `lux fix` now updates the whole system after refreshing the lists (keys first, with the usual question); when the system is older than the lists (also after a declined update), `lux install` offers to install together with a full system update, and refuses with a hint to `lux update` without a terminal and in the Store. Unrelated installs and IgnorePkg packages still go through.
- **The installer erases only the disk that was selected, and a hand-prepared encrypted system boots** (`luxos-installer` 1.1.0-44, `luxos-i18n` 85): right before `wipefs`/`sgdisk --zap-all` (whole disk, next to other systems, existing partition and manual partitioning) the size, model, serial number and WWN of the selected disk are checked again (from the graphical installer also the size and model of the chosen disk) and the write goes through the stable `/dev/disk/by-id` path; if /dev/sdX now belongs to another disk (USB unplugged/plugged in), the installation stops and erases nothing. The “partitions already mounted at /mnt” mode with a manually opened LUKS/LVM under / gets `rd.luks.name` and the `sd-encrypt`/`lvm2` initramfs hooks (it did not boot before).
- **LuxOS Care: fallback kernel after a snapshot rollback and ESP cleanup during a manual update** (`luxos-care` 1.0.0-25): after rolling back to a snapshot the “previous kernel” entry kept the old system's kernel, whose modules the restored system may not have – it now gets the restored system's fallback kernel (kernel, modules and initramfs from it), otherwise the entry is removed. The ESP cleanup no longer deletes an `initramfs-…img.tmp` that mkinitcpio is writing during a manual `lux update` – only files older than an hour and not open by any process.
- **Installer: fixes from a visual review** (`luxos-installer` 1.1.0-45, `luxos-docs` 1.0.0-78, `luxos-i18n` 1.0.0-86): sizes in decimal GB everywhere (manual partitioning no longer uses GiB), the summary shows the "will be erased" warning at the top and the window fits the screen (1280×800, 1024×768), taller device tree in manual partitioning, clearer step names ("Target Disk", "Updates & Maintenance" in all languages) and anonymous usage count wording ("on - once a week, no personal data", same in the Setup Assistant), local time in the wizard language, no "Min.." in German; the summary no longer crashes without a selected disk (demo mode).
- **Dates and numbers follow the language outside Mail too** (`luxos-greeter` 1.0.0-15, `luxos-desktop` 1.1.0-84, `xfce4-screensaver` 4.20.2-1.7, `luxos-account` 1.0.0-11, `luxos-backup` 1.0.0-7, `luxos-weather` 1.0.0-10): dates on the login and lock screens, in the top bar (and its tooltip), the Today widget, the Clock world clock, the screensaver, the Tour and the LuxAI limit reset follow the system language – no more English names among Czech text when the locale isn't generated, and no fixed Czech "st 18. lis" format in other languages; decimal comma per language (sizes in Backups and App Reset, charts, battery power and energy, CPU load, network latency and speed, Weather precipitation); the "Enter Password" hint is readable on light and orange wallpapers (the field darkens according to the wallpaper brightness).
- **Website and Sandbox: small fixes from a visual review** (website, `luxos-sandbox` 1.0.0-11): the website header is no longer cut off on tablets (701–1000 px) – the menu moves behind the menu button; the Sandbox status badge (Ready / Not created) has enough contrast.
- **Settings windows and system apps: fixes from a design review** (`luxos-desktop` 1.1.0-85, `luxos-i18n` 87, `luxos-branding` 1.1.0-30, `luxos-docs` 79): **About This Computer** is a new window in the style of the other Settings windows (LSL instead of yad) – values aligned in one column, buttons without coloured icons and with room to breathe, no more cryptic “Shell lsh” row, “Linux kernel” instead of “Kernel”; it now also opens without a UTF-8 locale (LANG=C/POSIX, previously “Invalid byte sequence in conversion input”). **System Monitor, Feedback, Battery & Power, Desktop & Dock, Router, Keyboard Shortcuts and What's New** fit on a 1366×768 or 1280×800 screen (height from the work area without the menu bar, the content scrolls) and can no longer be shrunk to an unusable ~200 px. **Screen Saver & Lock, Keyboard Layouts, Bluetooth, Fingerprint Login, Profile Picture and Displays** are as tall as their content – no empty area at the bottom. **What's New** says where to click instead of showing terminal commands: the clock in the middle and rounded corners of the menu bar are new switches in Desktop & Dock › Menu Bar, and LuxAI explains Secure Boot on an already installed system. **Feedback** has Settings-style switches instead of tiny check boxes, and the Send button stays readable while disabled. **Battery & Power** on the power adapter with a full battery shows “Charging complete · running on the power adapter” instead of “-”, and hides the charge-cycles card when the battery does not report it. **Router** without a connection disables Show, Test and Measure with the hint “Not connected to a network”. **Displays**: the text size slider labels no longer sit off their marks (the chosen size is shown under the slider). A check of the whole repository found 53 packages: setuid in `cnrdrvcups-lb` and `cnrdrvcups-sfp` (status program `pksmncapr`), world-writable folders and files in Canon (`/etc/cngplp2`, `/usr/lib/bjlib/*.ini` in PIXMA, MAXIFY, cnijfilter and scangearmp) and Brother drivers (`inf/br*rc` and `inf` folders) – the next build fixes all of them.
- **Security: network printers and printer management** (`luxos-printing` 1.0.0-17, `luxos-docs` 74): automatic setup of network printers treats announcements from the local network (mDNS) as unauthenticated – it adds only IPP Everywhere/AirPrint printers with a valid name, service type and the `local` domain, the printer identifier (UUID) only in a valid format (otherwise it never gets into the queue address), the description without control characters, and by itself at most 5 printers per hour and 20 in total (more can be added with + in Printers & Scanners). The network watcher runs a check at most every 10 s – before, a flood of announcements postponed it forever. Drivers are never installed because of a network announcement (only for USB printers). Removing a printer and cancelling another user's print job now ask for an administrator password (polkit `org.luxos.printing.admin`, remembered for a few minutes); adding a printer, the default printer, resuming a queue and cancelling your own jobs stay password-free. Tests: announcement validation, limits, announcement flood, helper permissions and polkit rules.
- **LuxOS Store: the app list is on screen right after opening** (`luxos-store` 1.0.0-20, `luxos-docs` 74; complaint "the app list takes quite long to load"): before showing anything the Store used to read the repository databases, installed packages, AppStream and the `.lux` index one after another, and with an older catalog it also waited for the download – 2.7 s on the development PC, 9.4 s with an older catalog on a slow network, 13.4 s offline, 7.5 s on the first start, all behind a spinner. Now it shows the list from its last run at once (`~/.cache/luxos-store/store-snapshot.json`, per language and catalog channel) and loads everything else in the background at the same time: the first app card is drawn after 0.25 s in every case (offline and on a slow network too) and the full load takes 1.6 s instead of 2.7 s. The open page then only fills in (button states, icons, new apps) without jumping to the top or back to Discover; an app page opened from the quick list fills in its description and screenshots. Nothing waits for the network: the catalog is refreshed in the background with a conditional request (ETag – an unchanged catalog is not downloaded again) and a changed one updates the list immediately, missing icons are downloaded together in parallel, the `.lux` index is added when it arrives. On the very first start placeholder cards instead of a spinner, LuxOS apps as soon as the databases are read (1.1 s instead of 7.5 s) and Arch apps after AppStream. Long lists (categories with hundreds of apps) show the first screen at once and add the rest in batches, icons are decoded in the background at display size and kept in memory; the Store code is a precompiled module and the sharp window icon is set after the first frame. Also fixed: card buttons in lists did not update after an install (the page's card list was cleared right after the cards were built – a card stayed on "Get" with no progress), downloaded icons redrew the whole page (jump to the top, an open app page went blank), a search given at start (`luxos-store text`) was replaced by Discover once loading finished, and the Installed page blocked the window while running `lux-engine` and `flatpak`. Tests: `test_store_startup.py` under xvfb with a 600-app catalog and deliberately slow loading (first card from the saved list within 1 s – measured 0.15 s, first start with placeholders, offline with an old catalog, background refresh with ETag and 304, slow `.lux` index, a 600-app category in batches, search at start, app page from the saved list) and installing from a card in `test_store_gui.py`.
- **Programs keep starting after the computer is renamed**: a real case – the computer name changed during the session (jupiter → luxos), LightDM had written the screen access in `~/.Xauthority` only for the old name, so every newly started program ended with "Authorization required … Failed to open display" – Launchpad, Clock and screenshots stopped working until an entry was added by hand. The same would happen to anyone renaming the computer in Settings, with `hostnamectl` or `lux system`, or joining a domain with a full name. At sign-in (`/etc/X11/xinit/xinitrc.d`, before the first program of the session) LuxOS now adds an entry valid for any computer name with the cookie the X server really accepts; the entry for the computer name stays, old entries of the same display with an invalid cookie are removed. Running sessions get it right after the update, even those that have already changed the name. The cookie is never printed or passed in arguments; on a network disk (shared home) nothing changes. The login screen, the screen lock and administrator password prompts are unchanged. Tested with a real cookie (Xvfb `-auth`) and a name change in a private namespace (`unshare -U -u`).
- **Old developer copies of LuxOS programs no longer override the system ones**: a real case – copies of `luxos-clock-app`, `luxos-widgets`, `luxos-tour`, `luxos-app-studio` and `luxos-icon-studio` from earlier experiments were left in `~/.local/bin` and `~/.local/share/applications`; `~/.local/bin` comes before `/usr/bin` in PATH, so the old versions ran (the session even started the old `luxos-widgets`). At sign-in, `lux*` files that hide a file from a package and are **older** than it are now moved to `~/.local/share/luxos/shadowed/<date>/`, and one calm notification says which and where (in all 12 languages). Nothing is deleted; newer copies (a developer is working on them), hidden menu entries and files no package installs stay. To turn it off: the file `~/.config/luxos/keep-local-overrides` or `KEEP_LOCAL_OVERRIDES=1` in `~/.config/luxos/appearance.conf`. Session components and LuxOS autostart entries (session, Dock, Lux Guard, Secure Boot, sandboxed app launchers) start with the full `/usr/bin` path, so a copy in PATH cannot hide them.
- **The bar and widgets use the wallpaper that is really on the desktop** (`luxos-desktop` 79): without a saved choice xfdesktop shows the wallpaper of workspace 0 on all workspaces ("Apply to all workspaces" is on by default), but the bar painted the wallpaper stored for the active workspace – after setting a wallpaper in the advanced desktop settings it showed an old wallpaper on the other workspaces that was not on the desktop. - **Security: hardening from our own audit** (`luxos-guard` 1.0.0-10, `luxos-desktop` 79, `luxdrop` 8, `luxos-mail` 1.0.0-12, `luxos-installer` 42, `luxos-i18n` 81, `luxos-docs` 74, ISO): **Lux Guard** – only the real Lux Guard session helper may answer "Run Anyway" questions, another program cannot take its place; `luxos-guard allow` run by a user is confirmed in the Lux Guard window (administrators with `sudo` still allow directly); after an update the helper switches to the new version by itself, without signing out. **Fingerprint** – fingerprint sign-in (login screen, lock screen, sudo, polkit) now respects the temporary lockout after many failed attempts, `/etc/nologin`, the login shell and account validity just like a password; the rule 20 failures in 30 s → 1 minute stays. **LuxDrop** – LocalSend devices are clearly marked as not verified and show a device code to compare, their files are always saved only after you confirm, and LuxDrop warns loudly when a device with a known name shows a different key. **Mail** – a mailbox name containing a line break is refused. **OEM** – the setup assistant's `sudo` rule is always removed when setup finishes, even if a power cut interrupts the finishing step. **Live ISO** – the root password is locked (administration via `sudo` of the live user, the emergency shell still works), the SSH server is off and, even if started by hand, refuses empty passwords and root logins. **System protection** is on for new installations from the first start; the documentation explains how to turn it on for an older installation.
- **Organization network: joining a domain, offline days, sign-in denied by Group Policy, clashing account names, password change and shared folders without a password** (`luxos-domain` 1.0.0-4): joining a real domain failed at the administrators step – sudo 1.9.17 rejected the rule `%"domain admins"` as an "empty group" (now `"%domain admins"`, tested with the real `visudo`); `lux domain set offline-days 1` (and the same in Settings) failed with the default 7 days of administrator rights and changed nothing – a shorter offline sign-in now also shortens the administrator rights; a domain account with the same name as a local one (`jan`) was shown as `jan`, the local account's name – now `jan@company.local` with its own home folder, and an override written by an earlier version is repaired by itself at the next connection check; changing an expired domain password at sign-in always ended with "Permission denied" (a PAM jump past the end of the `password` stack, also repaired on computers already in a domain); organization shared folders asked for a password even after signing in – Samba (`smbclient`, `gvfs-smb`) has its own Kerberos that cannot read a ticket stored in KCM, the sign-in ticket is now kept in the file `/tmp/krb5cc_UID` (computers already in a domain are converted by the package update).

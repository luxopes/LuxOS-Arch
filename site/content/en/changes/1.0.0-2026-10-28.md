## 1.0.0 "Sirius" – 2026-10-28 (test release, staging)

A test release for installing on real hardware: both the ISO and the updates come from the non-public **staging** channel;
users of 0.9.12 get 1.0 only after the 1.0.1 release.

### New
- **Stable / staging update channel**: `[general] channel` in `/etc/lux/lux.conf` is `"stable"` (default, released versions) or `"staging"` (pre-release test builds for testers). On staging the LuxOS repositories (`[luxos]`, `[luxos-apps]`, `[luxos-drivers]`, `.lux` packages and Store icons) are read from `https://luxos.lux-ai.cz/staging/` instead of `…/repo/`; Arch Linux and custom repositories stay the same. It applies everywhere (lux, `lux-engine`, LuxOS Care, Store). Switch with `updates.channel` in `/etc/luxos/system.lsl` and `sudo lux system apply`, or `lux-config set-channel`; `lux config check` shows the channel. The test ISO (`LUXOS_CHANNEL=staging`) uses staging in the live and installed system.
- **LSL 0.10.7** (LuxIR backend 0.4.4): new modules `net` (TCP/UDP, multicast), `tls` (TLS 1.2/1.3, custom certificates, pinned keys, ALPN), `crypto` (EC P-256, ECDSA, SHA-2, HMAC) and `mdns` (Avahi); 13 bugs found while rewriting LuxAI fixed; new `lsl-test` command.
- **LuxAI rewritten in LSL: faster start, less memory** (`luxai` 2.0.0): LuxAI is now a native LSL program instead of Python, with the same window, behaviour, permission rules and administrator mode. The window appears in **~340 ms instead of ~515 ms** and uses **96 MB instead of 118 MB** RSS after start. Settings, sign-in and chat history carry over unchanged, and the administrator helpers keep their paths, so an enabled "no password" mode still applies. New: **calendar** – LuxAI can read LuxOS Calendar events (in Chat and Agent) and, in Agent, add, change and delete them after you confirm on a card; `luxai --remote-session` for LuxOS Companion; sharp window icons at 16–256 px. LuxAI no longer needs Python or PyGObject.
- **Clicking a notification shows its full text** (modified `xfce4-notifyd` in `[luxos]`): a click no longer closes the notification but expands it – full title, text (shortened to 3 lines) and action buttons; a second click runs the default action (e.g. opens the message) and closes it. Notifications with nothing to expand run the default action right away. A small **×** in the top-left corner appears on hover to close it (as on macOS); hovering still pauses the countdown, and right/middle click closes it as before.
- **Sorting in Launchpad**: buttons below the grid for **Alphabetical**, **Recently used**, **Most used** (default, as before) and **By category** (Internet, Office, Graphics, Multimedia, Development…, alphabetical within each), also `Alt+1`..`Alt+4`. The choice is remembered per user (`~/.config/luxos/launchpad-sort`). App launches are counted only on the computer (`~/.local/share/luxos/launchpad-usage.json`, app IDs, counts and last launch time, never sent anywhere). Changing the order re-sorts the tiles in the open window without closing or flickering, and opening Launchpad stays as fast as before.
- **Sound switches to a connected monitor by itself** (HDMI/DisplayPort), as well as to USB and Bluetooth devices, and switches back when unplugged. Previously the HDMI port only appeared on a sound card that stayed in its analog profile, so nothing switched. `luxos-hub` now watches card changes (`pactl subscribe`, no polling), switches the card to the best HDMI profile (keeping the microphone), sets the default output and moves playing streams. A manual choice wins: if you pick another output after an automatic switch, nothing is reverted on unplug. Devices connected at login are not switched.
- **Phone – LuxOS Companion** (`luxos-companion`, new package in the base install): the computer side of the LuxOS Companion 0.2 Android app over Bluetooth (RFCOMM with mandatory authentication and authorisation). Pair the phone in Bluetooth settings first (LuxOS never makes itself visible by itself); on the first connection LuxOS asks **"Allow phone … to connect to LuxOS?"** – pairing alone grants nothing. Settings › **Phone** shows the connection, allowed phones with Remove, and switches for sharing the phone's location with Maps, LuxAI requests from the phone and saving notes to Calendar. **Live location in Maps** from the phone's GPS (only with consent, valid at most 15 s, greyed out when stale). **LuxAI from the phone** via `luxai --remote-session` (streamed answers, Stop, text never goes to a shell, action confirmations stay on the computer). **Notes to Calendar** as all-day or 30-minute events in the phone's time zone, written safely without touching the rest of `events.ics` and never duplicated; Calendar now also picks up events added by other programs before saving. D-Bus interface `cz.luxos.Companion1` for other apps. Documentation `companion.md`.
- **LuxDrop with the LuxOS Companion 0.3 Android app** (`luxdrop`): the app's LuxDrop tab uses the native LuxDrop protocol (TLS 1.3, pinned keys, verification code) instead of LocalSend mode. The phone sends a file to the computer's address after you paste the key fingerprint from `luxdrop id` (or Settings › Security) and resumes interrupted transfers; in receive mode (10 minutes) the phone shows up in LuxDrop among nearby devices and accepts up to 16 files and 1 GiB. The LuxDrop receiver now always picks AES-256-GCM by its own order, which the app requires. Verified against the app in both directions. Documentation `luxdrop.md` and `companion.md`.
- **LuxDrop understands LuxOS Companion 0.3.2** (`luxdrop`, `luxos-i18n`): when the phone declines an offer, LuxDrop now says why in your language based on the error code ("Too many files or too much data for the recipient", "Not enough disk space", "The recipient did not answer in time", "Data was damaged on the way. Nothing was saved" …) instead of the text sent by the other side, which is now only a shortened detail. This applies to all transfer errors in the window and on the command line. With Python 3.15 LuxDrop also offers ChaCha20-Poly1305 as a sender, so phones without hardware AES use the faster cipher. Verified in 33 scenarios against the app.
- **Joining a company network – Windows domain (Active Directory) and Samba AD** (`luxos-domain`, `lux domain`): LuxOS joins an existing domain without any change on the domain side. Settings › **Company Network** (domain pre-filled from the network, **Find** shows e.g. "Microsoft Active Directory – firma.local – 2 controllers", admin name and password, step-by-step progress), a new **Organization** step in the installer (graphical, text and unattended with `DOMAIN=`, `DOMAIN_USER=`, `DOMAIN_PASSWORD=`, `OU=`) and in the Setup Assistant (OEM). The login screen gets **Other user…** (accepting `jan`, `jan@firma.local` and `FIRMA\jan`). **Offline login** with a cached password for 30 days, changing an expired password right at login, short user names, **domain administrators** with `sudo` and LuxOS admin dialogs (for 7 days without contact to the domain), "Allow/Deny log on locally" GPOs, `lux domain login allow GROUP`, company shares and Windows print servers via Kerberos without another password, Kerberos for company websites in Firefox. The domain admin password is never stored. A system snapshot is taken before joining and everything is rolled back on error; **leaving** restores the original login setup and keeps home folders. Built on SSSD, Kerberos (KCM), `adcli` and `realmd` (verified copies in `[luxos]`). Documentation `domain.md`, `man luxos-domain`.
- **Organization policies in `lux system`** (`/etc/luxos/system.d/NN-name.lsl`): LSL fragments from an organization (domain, later LuxOS Directory) are merged with your own `/etc/luxos/system.lsl` in name order. Your file wins, except for entries with `config.mkForce`, which are **locked** – a different value is an error naming the organization and policy; `config.mkDefault` is only a recommendation. Lists (packages, services, ports…) are combined. `lux system diff` shows which policy each change comes from, `lux system show --origin` lists the origin of every value and `lux system locks` the locked entries. Anything that disappears from a policy stays as it is – nothing is uninstalled by itself. New `domain` key (administrators, who may log in, offline days).
- **Our own LuxOS Terminal with images** (`luxos-terminal`, replaces xfce4-terminal): a small C program (GTK3 + VTE) in macOS style – tabs (Ctrl+Shift+T, shown from two tabs on, a + button in the title bar), new tabs and windows in the same folder, a dark profile with a black, slightly transparent background (light or follow-system optional), search (Ctrl+Shift+F), Ctrl+click links, font size Ctrl+plus/minus/0, Ctrl+Shift+C/V, tab titles by folder, a question before closing a running program, remembered window size. It shows **SIXEL images** (img2sixel, chafa, timg…), and fastfetch shows the real LuxOS logo as an image; LuxOS ships its own `vte3` with SIXEL restored. Faster and lighter than xfce4-terminal: a window in 175 ms instead of 203 ms, another window in 53 ms instead of 108 ms. Super+T, Ctrl+Alt+T, Dock, "Open Terminal Here" in Files and `Terminal=true` apps open the new Terminal. Settings `~/.config/luxos/terminal.conf`, documentation `terminal.md`.
- **Our own LuxOS Text Editor** (`luxos-text`, replaces Mousepad): a small C program (GTK3 + GtkSourceView 4) in macOS style – a folder tree sidebar (F9, **+** for a new file or folder, refreshes by itself), file name, language picker and an **(i)** document info popover in the title bar, a document outline (Markdown headings, functions and classes) with previous/next arrows, line numbers, syntax highlighting including LSL, wrapping, invisible characters and a status bar with line/character/word counts, position, **encoding** and **line endings**. Encodings are detected on open (UTF-8 with or without BOM, UTF-16, Windows-1250, ISO 8859-2, Windows-1252, Windows-1251) and kept on save together with line endings. Find and replace (Ctrl+F, Ctrl+H, regular expressions, "2 of 7"), go to line (Ctrl+L), tabs, recent files, drag and drop, a warning when another program changes the file, and a prompt for unsaved changes. Faster and lighter than Mousepad (a small file opens in 164 ms instead of 214 ms with 19 instead of 27 MB). It is the default app for text and source files; existing profiles switch from Mousepad once after login, Mousepad is removed by `lux update`, and the `mousepad` command still opens Text Editor. Settings `~/.config/luxos/text-editor.conf`, documentation `text-editor.md`.
- **System snapshots before every update and rollback from the boot menu** (`luxos-care`): before every package change (`lux`, Software Update, Store) a read-only Btrfs snapshot of the system is taken (the last 5 plus the last one with the previous kernel, 2 when space is low; `SNAPSHOT_KEEP`, `SNAPSHOTS=no` in `/etc/luxos/care.conf`). The kernel and initramfs the system boots with are saved alongside, so a snapshot still boots after a kernel update. The boot menu (hold Space, Esc on GRUB) offers "LuxOS (before update of …)": the snapshot boots read-only with a temporary in-memory layer, and after login a notification offers **Keep This Version**. Permanently: `lux rollback`, plus `lux snapshots` and `lux snapshot`; the current system stays as a "before rollback" snapshot, nothing is deleted, and automatic updates then wait 3 days.
- **The whole system in one file** (`lux system`, like `configuration.nix` in NixOS): `/etc/luxos/system.lsl` in LSL describes the wanted packages, Flathub apps, services, users and groups (no passwords, optionally `password_hash`), hostname, language, time zone, keyboard layout, LuxOS Care mode, Lux Guard, firewall and kernel parameters. `lux system show`/`init` creates the file from the current computer, `check` validates it, `diff` shows changes (also `--json`), and `apply` first takes a system snapshot, shows the difference, asks (nothing changes without `-y`) and applies; `lux rollback` undoes it. Only what is in the file is managed; packages never listed are removed only with `"remove_unlisted": True` (never the LuxOS base, kernels or essential services). The file is evaluated by a sandboxed `lsl config` (no files, network or programs, with a time limit). Errors are clear, with the location and advice, in all languages. Example `/usr/share/doc/lux/system.lsl.example`, documentation `man luxos-system`.
- **All important settings in `/etc/luxos/system.lsl` right from installation** (`lux system`): the installer creates the file at the end of installation (OEM after the Setup Assistant), and existing systems get it once when `lux` is updated, if it does not exist yet (it is never overwritten or recreated). Right afterwards `lux system diff` reports that the system matches. The file is written for beginners, in sections with explanatory comments in the system language. **No passwords** – neither user password hashes nor Wi‑Fi/VPN passwords. Newly managed: **network connections** (`network.connections` via `nmcli`, with extra confirmation before touching the connection in use), **printers** (`printers` via `lpadmin`), **power** (`power`: lid, idle suspend, power profile), the **boot menu** (`boot`: timeout and default entry), the **process scheduler** (`kernel.scheduler`), **drivers** (`drivers`), **regional formats** (`formats`) and the **text console** (`console`), **lockout after failed passwords** (`security.faillock`, LuxOS default 20 failures / 30 s → 1 minute), **defaults for new users** (`new_users`: appearance, wallpaper, Dock apps, default browser, editor and mail, screen lock) and **repositories** (`repos`, check only). **`lux system fix`** brings the system back to the state in the file and is also in LuxOS Recovery ("Repair Settings"). Documentation `man luxos-system`.
- **LuxOS Recovery** in the boot menu (it boots from the newest snapshot, so it works even after a broken update): disk check (read-only btrfs scrub and check, fsck of the EFI/boot partition; repair only after confirmation, never `btrfs check --repair`), rollback to a snapshot and **reinstalling LuxOS while keeping /home and accounts** (same apps, accounts and passwords, language, keyboard, Wi‑Fi, disk encryption and enabled services are carried over; the original system stays as a snapshot until the install succeeds). Commands `luxos-care disk-check`, `luxos-care reinstall`.
- **System protection** (`luxos-care`, a first step towards an "indestructible" system like macOS's Signed System Volume): system files in `/usr` are read-only and may only be changed by package changes via `lux`, Software Update, Store or `lux system apply` – `/usr` is unlocked just before the transaction and locked again right after. Updates still apply immediately without a reboot; `/etc`, `/var`, `/home`, `/opt` and `/usr/local` stay writable. Protection never blocks booting (kernel parameter `luxos.protect=0` disables it for one boot). New installations have it on (`PROTECT=yes` in `/etc/luxos/care.conf`); older ones can turn it on in Software Update › System Protection or with `luxos-care protect enable`. **System file check** `luxos-care verify` compares all package files in `/usr` and `/opt` with the package database and finds changed or missing files; `--repair` reinstalls the affected packages from signed repositories. It runs weekly in the background at the lowest priority, only on AC power, and notifies only when something is found (`--quick` checks ~225,000 files in 12 s). New keys `care.protect` and `care.verify` in `lux system`. Documentation `system-protection.md` and `man luxos-care`.
- **Reset app settings** (Settings, `luxos-app-reset`): a list of apps with settings in `~/.config`, `~/.local/share`, `~/.cache`, Flatpak and `~/.mozilla`; resetting an app moves its settings to `~/.local/share/luxos/app-settings-backups/<date>-<app>` (nothing is deleted, the backup can be restored). The keyring, LuxAI account, desktop and other sensitive folders are not offered.
- **Backups** (`luxos-backup`, Backups app): automatic incremental backups of your home folder to an external (USB) or network drive (SFTP, SMB share) every hour, only on AC power (paused on battery, in Battery Saver and on metered connections for network drives). Plugging in a new drive offers "Use this disk for backups?"; FAT/exFAT/NTFS drives can be prepared (btrfs with zstd), optionally encrypted (LUKS2, password in the keyring). Unchanged files take no extra space. Keeps everything for 24 h, one backup a day for a month and weekly ones beyond; a full disk deletes the oldest backups with a notice. Restore from a timeline, browse folders, restore to the original place or elsewhere – an existing file is never overwritten; "Restore All" works on a new system too (`luxos-backup restore --all --source DISK`, also from the installer and LuxOS Recovery). Documentation `man luxos-backup`.
- **Profile picture** (`luxos-profile-picture`, in Settings, or Change Photo in LuxAI Account): a photo from a file or webcam, cropped to a circle (drag to move, wheel or slider to zoom). It shows on the login and lock screens, in the LuxOS menu, Control Center and LuxAI Account; without a photo a circle with your initial remains. Saved to `~/.face` and via AccountsService.
- **Manage your LuxAI account right in LuxOS** (LuxAI Account app, replacing the lux-ai.cz/settings page): pages Overview (Flash and Lite usage with percentages and reset date), Profile (change user name), Password & Security (change password with a strength meter – other devices are signed out, this computer stays signed in), Preferences (AI answer style, light website mode) and Privacy & Data (export profile, settings and web chat history to JSON without the token, terms, account deletion request with strong confirmation). What the server does not allow from the app gets an Open on Web button; e-mail changes go through support.
- **Transition after login** – after authentication the login screen leaves only the wallpaper, which hides the desktop being assembled; once the desktop, bar and Dock are drawn, it fades into the finished desktop in ~0.3 s (`luxos-session-cover --login`). It never delays login (at most 5 s); no animation in Battery Saver or with animations off.
- **Magnifier in the top bar** before Control Center opens Search (like `Super+Space`); existing profiles get it once after login (if you remove it, it does not come back).
- **Preparing for someone else (OEM)** – a shop or IT installs LuxOS without a personal account (installer "Prepare for Another Person (OEM)", unattended `OEM=1`). On first boot the owner is greeted by a full-screen **Setup Assistant** like on a new Mac: language, keyboard, Wi‑Fi, time zone, account (name, password, optional photo), LuxAI, disk password and maintenance; then they are logged straight into the new account and the LuxOS Tour starts. An unfinished assistant survives a power cut (it restarts on the same page).
- **Seal for the customer** – optionally the computer is first prepared in a temporary `oem` account (apps, hardware test), then a desktop button or `luxos-oem seal` deletes logs, caches, history and saved Wi‑Fi, creates a new `machine-id` and SSH keys, and the `oem` account disappears on the next boot.
- **Encrypted disk with OEM** – until first boot the disk is unlocked with a temporary key (no password); the owner chooses the disk password in the assistant (default = account password), and the temporary key is then removed. The process is safe against a power cut at any step.
- **Monitor arrangement like on macOS** (Displays › Arrangement): monitors as scaled rectangles that snap to each other's edges when dragged (no gaps or overlaps), a white bar marks the main monitor with the top bar and Dock (drag it or pick Main Display), and a Mirror Displays switch. Every change has a 15 s confirmation like resolution changes. The layout is saved per set of monitors (connector + EDID) and restored after login and when the same monitors are reconnected.
- **Another computer's files next to yours** (`luxdrop`, **Connect to Computer** app, `luxdrop connect`): a Files window split into your home folder and the shared folders of another LuxOS computer on the network, with drag and drop between them; the connected computer is also in the Files sidebar. On the other computer, LuxDrop › Settings › **Share Folders** (off by default, then only the Public folder; never hidden folders; the whole home folder only after confirmation). Every new computer must be allowed by the owner (**Allow Once / Always Allow / Decline**, with the same 6-digit code as LuxDrop on first contact); access is read-only unless changes are requested and allowed. Transfers use a sandboxed SFTP server tunnelled over LuxDrop's TLS 1.3 – no sshd and no admin password. Removing access ends the connection; a vanished computer is detected within ~45 s without freezing. TCP port 47924, `luxdrop share`, `luxdrop disconnect`.
- **Network management** (`luxos-router`, Router): network details (Wi‑Fi, IP, gateway, DNS, public IP on request), the router's web admin right in the app (HTTP and HTTPS, only home-network addresses – other links open in the browser; the router's own certificate only after confirmation; no passwords stored), devices on the network with their vendor by MAC address, and quick tests: ping the router and the internet, DNS and a download speed estimate.
- **The lock screen looks like the login screen**: moving the mouse or pressing a key no longer shows the Xfce dialog but the same look as login – desktop wallpaper, date and large clock, round avatar, name, a frosted password field with an arrow, messages (Caps Lock, wrong password, temporarily locked account, fingerprint), keyboard layout, network and battery, and **Switch User** (with more accounts), Sleep, Restart and Shut Down at the bottom. The "Desktop wallpaper and clock" screensaver looks like the idle login screen, so the transition is smooth without a black screen. Lock security stays in `xfce4-screensaver` (modified package in `[luxos]`).
- **A CPU load graph** can be added to the top bar (right-click the bar › Panel › Add New Items › CPU Graph); it is not in the default bar.
- **Weather** (`luxos-weather`, new package in the base install): current weather, 24-hour and 7-day forecast, several saved places and city search, a background matching the sky and custom icons. Data from Open-Meteo (no key), cached for 30 minutes, with the last forecast shown offline. The first place comes from the time zone; approximate location by IP address (ipinfo.io) only after confirmation. Units follow the language (°C and km/h, °F and mph in the USA) and can be switched. The calendar under the clock shows the weather for the selected place below today (e.g. "13° Partly cloudy · Prague").
- **Maps** (`luxos-maps`, new package in the base install): smooth OpenStreetMap maps (drag with inertia, zoom to the pointer with wheel/touchpad, double-click, keys), place and address search (Nominatim), routes by car, bike and on foot with time, distance and turn list (FOSSGIS/OSRM as on openstreetmap.org), favourite places, "What's here?" and more on right-click, copying coordinates and `geo:` links, opening `geo:` links from other apps. My location only after one-time consent (GeoClue with nearby Wi‑Fi via BeaconDB, otherwise roughly by IP), with an accuracy circle. Dark map following the system appearance. Follows OSM usage rules (own User-Agent, limited downloads, cache up to 300 MB, at most 1 query/s); offline it shows previously viewed places; "© OpenStreetMap contributors" is always visible. GTK3 + cairo: the window is drawn in 0.45 s with 44 MB. **Public transport** (Transitous open data): departing now, at a set time or arriving by – up to 3 connections with times, transfers, coloured line badges, platforms and real-time delays. **Departure boards** with the next 20 departures or arrivals refreshed every minute. **Nearby**: restaurants, cafés, shops, fuel and charging stations, parking, pharmacies, hospitals, hotels, sights, stops, toilets and playgrounds from OpenStreetMap (Overpass). For LuxAI and scripts, `luxos-maps --json search|reverse|route|transit-route|timetable|nearby|where-am-i|open` and route preview images with `luxos-maps --render-preview`. Documentation `maps.md`.
- **Navigation in Maps** (`luxos-maps`, `luxos-i18n`): a **Navigate** button for car, bike and walking routes and for a selected transit connection. A large banner at the top shows the next manoeuvre's icon, distance, instruction and street (translated), plus the one after; at the bottom the remaining time, distance, **arrival time**, a compass and **End**. The map follows your live position – phone GPS via LuxOS Companion first, otherwise GeoClue – with an arrow in the direction of travel, **heading up** or **north up**; moving the map stops following and shows **Re-centre**. **Off route** (more than 50 m) the route is **recalculated from your position** (at most every 15 s, considerate to the OSRM server); "You have arrived" at the destination; transit gets live Walk/Board/Get off steps with platforms and times. The screen does not blank or lock while navigating and is always released afterwards. Optional **voice guidance** (with `speech-dispatcher` or `espeak-ng`, off by default). The **Maps sidebar can be resized** by dragging (280–560 px) and its width is remembered. Documentation `maps-navigation.md`.
- **Wi‑Fi QR code** (`luxos-wifi-qr`): Control Center › "Share Wi‑Fi with QR Code…" shows the connected network as a QR code for a phone (password from NetworkManager, for system-wide networks after the admin password; the image can be copied). Without a connection, "Connect to Wi‑Fi with QR Code…" lets the Camera scan a network's QR code and connect after confirmation (`luxos-camera --scan-wifi`). QR codes are drawn and read by `zxing-cpp` (~2 MB).
- **New look of the LuxOS menu** (logo in the top bar, modified `xfce4-whiskermenu-plugin` in `[luxos]`): a translucent rounded panel like the other menus (light and dark), a round profile photo (or initial) with your name and a Log Out… button at the top, then a rounded "Search apps…" field. Favourite apps in taller rows on the left, categories with arrows on the right, the selected row softly blue and rounded. At the bottom **Lock Screen** and round labelled buttons **Restart**, **Sleep** and **Shut Down** (red). Chromium apps no longer have their own "Chromium Apps" category and live in Internet. Existing profiles get the new layout once after login (favourites are kept); the menu opens as fast as before.
- **New format of `/etc/lux/lux.conf` (TOML)** (`lux-engine`, `lux`): the package manager configuration has tables `[general]`, `[downloads]`, `[security]`, `[packages]`, `[paths]`, `[repo.NAME]` and `[include]` with `key = value` lines (quoted text, `true`/`false`, lists such as `hold = ["linux"]`). `lux` reads it directly. Errors report file and line; an unknown or misplaced key is only a warning in `lux config check` with a hint ("it belongs to [downloads]"). The older `key value` format from LuxOS 0.9 is still read; updating `lux-engine` converts `/etc/lux/lux.conf` and `conf.d/*.conf` once (same values, comments kept, original saved as `lux.conf.old-format`), manually with `sudo lux config migrate` (`--dry-run` shows the result). The installer, live ISO, sandbox and `lux-config enable-repo` write the new format; other tools use `lux_config.load()` (`lux-config json`).
- **Configuration backups are named after lux** (`lux-engine`): a new version of a modified config file from an update is now `*.luxnew` and a saved modified file of a removed package `*.luxsave` (instead of pacman's `*.pacnew`/`*.pacsave`). Updating `lux-engine` renames existing `*.pacnew`, `*.pacsave` and `*.pacorig` files in `/etc` once (never overwriting, logged in `/var/log/lux.log`). `lux configs`, `lux doctor`, `lux update`, LuxOS Care and Software Update recognise both old and new names.
- **Faster response and start** – a new process scheduler **scx_lavd** (sched_ext, `scx-scheds` package): under load, windows, input, audio and games get the CPU first. `luxos-scheduler.service` starts it only after the login screen appears (boot never waits for it); without sched_ext support, on error or repeated crashes the normal kernel scheduler (EEVDF) silently stays. Switch with `sudo luxos-care scheduler default|lavd`, `SCHEDULER=` in `/etc/luxos/scheduler.conf` or `kernel.scheduler` in `system.lsl`. The `linux-luxos` kernel has `HZ=1000`, full preemption and sched_ext. The boot menu no longer waits on GRUB (BIOS) either: `GRUB_TIMEOUT=0` with a hidden menu (hold Shift or press Esc), older installations switch once if they still have the LuxOS default; the previous kernel, snapshots and LuxOS Recovery stay in the menu. The splash now runs in parallel with network start, so the login screen appears about 0.3 s earlier.
- **A stronger Safe – also for signing keys** (`luxos-safe`, `luxos-backup`): new Safes and every password change use scrypt 2^18 (256 MiB, unlock ~0.7 s instead of 0.18 s), making password guessing from a stolen disk 4× more expensive; existing Safes offer **Strengthen Protection…** (same password, only the key wrapping changes). New passwords need at least 12 characters, show a strength meter and reject common words and patterns; old passwords still unlock and attempts are never locked out. **Recovery key**: shown once after creation to write down on paper (cannot be selected or copied), available again via **Recovery Key…** with the password; **Forgot Password…** uses it to set a new password. An unlocked Safe is mounted `nosuid,nodev,noexec`, gocryptfs runs without core dumps and `gpg-agent` for GnuPG folders in the Safe is stopped before locking. `luxos-safe check` shows the protection status. Backups now include the encrypted Safe (encrypted data only, never the unlocked contents). `./build.sh` looks for the repository signing key in the Safe first. Documentation `safe.md`: threat model and how to move GnuPG and Android keystore keys into the Safe.

### Changed
- **Installer: no pacman or Arch in Details** – the output of inherited tools (keyring setup, optional dependency lists) is no longer shown in the window, and tool and path names are LuxOS ones (`lux`, `/etc/lux`). The full log (`/var/log/luxos-install.log`, Save Log) stays unchanged for troubleshooting; package names are unchanged.
- **More thorough checks of community (AUR) packages** (`lux`): the build script check now has two layers. (1) Fixed offline rules (no AI) scan all repository files and now also catch downloads straight into `$pkgdir` or `/tmp` with `chmod +x`, obfuscation via `rev`/`eval`, changes to `/etc/hosts`, `resolv.conf` and `ld.so.preload`, persistence (autostart, user services), setuid, disabling the firewall or security services, replacing system programs, data exfiltration and key/cookie theft, crypto mining, sources from bare IPs or look-alike domains and missing checksums for remote downloads. (2) The review is done by **two independent LuxAI models – Lite and Flash**; the stricter answer wins and "safe" only counts when both agree. File contents are passed to the model as data and instructions hidden in them are ignored (prompt-injection resistance). Every verdict comes with a reason. On an evaluation corpus (22 real AUR packages + 27 malicious variants) the check flagged **all 27 malicious ones as dangerous (0 as safe)** and no real package as dangerous.
- **No "waves" wallpapers** (`luxos-waves-dark`, `luxos-waves-light`): only the new wallpapers remain in LuxOS 1.0. Anyone who had waves set gets Flow in the same mode (dark or light) after login.

### Fixed
- **LuxOS Companion: the phone did not connect** ("read failed, socket might closed"): the Bluetooth service record (SDP) had no RFCOMM channel, so Android could not find it. The service now has fixed channel 22 and its own SDP record; verified with a real phone.
- **No more "Failed to start BAMF" errors in the system log on logout and re-login**: the Dock's `bamfdaemon` service starts only when an X server is available.
- **"Install LuxOS" no longer appears in Launchpad after an OEM install**: the installer package stays for the Setup Assistant, but its launcher is hidden on the installed system.
- **`luxos-backup restore`/`list` outside the desktop session** (ssh, another console): when mounting the backup disk needs the admin password, it asks in the terminal, otherwise it clearly points to the Backups window or a desktop terminal (previously a D-Bus "NotAuthorizedCanObtain" error).
- **Safe: closing the admin password dialog** while creating a Safe now says "Authentication was cancelled. Nothing was changed." instead of "The Safe folder could not be created."
- **Launchpad and Search without black corners with the compositor on** (`rofi` from `[luxos]`): rofi took the screen's last 32-bit visual, which on X servers with GLX (e.g. VMs with llvmpipe) may lack alpha, so rounded corners were black. It now picks a visual with alpha via XRender.
- **OEM: the first login after the Setup Assistant really is in the language the owner chose** (`luxos-oem`): the account language is written to AccountsService when the account is created; previously the first session was in English.
- **Community (AUR) packages with signed sources build in the sandbox** (`luxos-sandbox`): authors' keys from `validpgpkeys` (e.g. `neofetch`) are fetched into the sandbox user's keyring before building (the host is untouched, like yay/paru); previously the build failed with "unknown public key … One or more PGP signatures could not be verified".
- **LuxDrop: "Show in Folder" in the received-file notification did nothing** when the receive folder was the default. It now opens Files with the received file selected.
- **All apps and the top bar crashed at once** after running out of memory: earlyoom killed the accessibility bus (at-spi), and when it restarted all running GTK apps quit. earlyoom now leaves it alone (`luxos-tweaks`).
- **LuxDrop closes the connection right after declining or finishing a receive**: the receiver closed only the raw socket, not the encrypted connection, so a sender waiting for the end (the Android app) hung after "Decline" until it timed out.
- **Command help in the system language instead of developer notes**: `luxos-care -h` on an English (or other) system printed a Czech developer docstring. Help and usage errors now have an English source translated into all 12 LuxOS languages for `luxos-care`, `luxos-backup`, `lux domain`, `luxos-safe`, `luxos-companion`, `luxos-app-reset`, `luxos-scan`, `luxos-unfreeze`, `luxos-hwdetect`, `luxos-install`, `luxos-oem`, `luxos-appearance`, `luxos-brightness`, `luxos-datasaver`, `luxos-displays`, `luxos-powersaver`, `luxos-splash`, `luxos-network-login`, `luxos-portal-check`, `luxos-terminal`, `luxos-text` and `luxdrop` (including argparse texts). `luxos-install --help` no longer asks for the admin password and `lux --help` has aligned columns. The browser page after connecting a LuxAI account is in the system language (previously Czech only). A new test checks the help of all commands in English, Czech and German.
- **Login transition without a black screen in QEMU and on drivers without glamor**: the X server there does not keep the last login-screen frame, so `luxos-session-cover --login` showed ~2 s of black. The login screen now also saves the frame to the user's LightDM folder and the transition uses it when the server's frame is black; otherwise at least a blurred wallpaper, never black.
- **LuxOS Companion asks only once**: an approved phone is marked as trusted in BlueZ (Remove in the Phone window revokes it) and the LuxOS Bluetooth agent no longer shows its own "Allow … to connect?" prompt for the Companion service. Previously two prompts could appear.
- **Live system: no partition icons of the target disk on the desktop after installation** – the live desktop shows only removable (USB) drives, not internal ones (they stay in Files). The installed system is unchanged.
- **LuxOS Recovery no longer reports a "dirty" EFI partition after a hard power-off**: a mounted FAT partition always has the kernel's "dirty" flag, which the disk check no longer treats as an error (real errors are still reported). The installer always gives the EFI partition a boot-time check in `/etc/fstab` (pass 2), so `systemd-fsck` silently clears the flag after a power cut.
- **`lux remove` keeps modified config files as `*.luxsave`**, as documented (previously it deleted them like `pacman -Rns`); `-n`/`--nosave` deletes them too.
- **Notifications no longer cover open top-bar windows**: new notifications used to appear over Control Center, Calendar, the LuxOS menu, bar menus, Launchpad and Search. A notification that would cover such a window now waits hidden (countdown paused) and appears once it closes; otherwise notifications stay above windows. Works for rofi and panel menus too, without D-Bus or polling.
- **Sliders in the top-bar sound menu**: the second slider was microphone sensitivity – without a microphone even the output's "Monitor" – so it changed nothing audible and looked broken. The sliders now have labels "Output: <device>" and "Input: <microphone>", and without a microphone the input slider is hidden. The Sound slider in Control Center now unmutes muted audio when moved.
- **Launchpad and Search without black corners** without a compositor (disabled, VM without 3D acceleration): window transparency is not shown without a compositor, so the rounded corners were black; rofi from `[luxos]` now uses a screenshot of what is under the window as the background.
- **Sharp icons in Alt+Tab even for apps that set their icon again** (e.g. Bluetooth): the large icon is restored on every window activation, not just the first (GTK later replaced it with a small 48 px one that Alt+Tab stretched).
- **Terminal command history is no longer lost** – every command is written to `~/.lsh_history` immediately, not when the terminal closes (with many windows, a crash or logout most commands were lost); with ble.sh history is shared between terminals.
- **Notifications move up after closing one** – a closed notification no longer leaves a gap; the rest move to the screen edge.
- **Lux Guard warns about the same file only once, even with several copies** (by content, not path), and restarts in its new version after an update (previously the old one ran until logout).
- **Lux Guard warnings disappear by themselves** (after 10 s instead of a critical notification that stayed until closed) and do not go into the notification history; the same file is reported only once (again only after it changes). Details remain in `luxos-guard log`.
- **Captive portal sign-in (train Wi‑Fi, hotel) even when the network's DNS does not answer**: the portal check now runs for 2 minutes instead of 15 s, also tries the network gateway and public DNS and finally the last known check address; every result is in the system log (`journalctl -t luxos-portal-check`). Manual **Sign In to Network…** in Control Center under Wi‑Fi when the network has no internet. `luxos-hub` restarts into its new version after an update and the session restarts it if killed – fixes apply right after `lux update`.
- **Alt+Tab tells windows of the same app apart**: instead of identical icons it shows a preview of each window's content (with the app icon), and the selected window is raised so you can see all of it – for example which terminal is which.
- **Frozen desktop** (the mouse moves but clicks and typing do nothing): from a console (Ctrl+Alt+F3) `luxos-unfreeze` saves a report about the display server, window manager, memory and processes and restarts the window manager and bar while open apps keep running. When the display server or window manager does not respond for 30 s, LuxOS saves the report by itself (`~/.local/share/luxos/freeze-reports`).
- **Screenshot**: with the toolbar open it can again be closed with Esc and captured with Enter; other keys keep going to apps (the toolbar does not grab the keyboard and the screen is not frozen, so you can keep opening and clicking things).
- **Screenshot opens instantly and stays on top**: rewritten from Python to LSL; the toolbar, selection and preview are prepared in the `luxos-hub` session process, so after Print / Shift+Super+5 the toolbar appears in ~5 ms (previously ~0.4 s). When another window activates or opens, the toolbar, selection and preview no longer disappear behind it. Esc reliably closes the toolbar, selection, timer countdown and preview even when another app has the keyboard; while recording, Esc stays with apps and recording stops with the Stop button. New `luxos-screenshot --close` switch.
- **Lux Guard and Python venv**: an empty downloaded file (e.g. a failed script download) is no longer flagged, and empty `__init__.py` files in a venv are not treated as its "copies" – `python -m venv` and pip inside it work without prompts or the Sandbox.
- Installer: the **Programming** set also includes `vim` (next to `neovim`).
- **Captive portal sign-in even with Tailscale/VPN DNS** (e.g. a school guest network): when system DNS did not work behind the portal, NetworkManager only reported "limited connectivity" and the sign-in window never opened. The new `luxos-portal-check` asks the network's own DNS server (from DHCP) directly and detects the portal redirect; the sign-in window gets both the portal address and IP.
- **Workspace switcher** (if you add it to the bar) shows workspace numbers in bar colours with the active one in blue, instead of grey blocks with thumbnails; thumbnails can be enabled in its settings and then have a transparent background. Workspaces with default names "Workspace N" are named by number.

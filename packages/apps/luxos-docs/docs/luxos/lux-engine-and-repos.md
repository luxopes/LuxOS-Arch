# lux-engine, repositories and signing

## No pacman command

LuxOS is based on Arch Linux but has **no `pacman` command and no pacman configuration**
(`/etc/pacman.conf`, `/etc/pacman.d`). The package manager is [`lux`](package-management.md),
configured in `/etc/lux/lux.conf` (own format, see
[package-management.md](package-management.md#configuration-etcluxluxconf)). Its core is the package
**`lux-engine`**: libalpm and the tools of Arch Linux's `pacman`, built from exactly the same
sources, checksums and patches as Arch's `pacman` package (currently Arch tag
`7.1.0.r9.g54d9411-3`, LuxOS `pkgver=7.1.0.r9.g54d9411`, `pkgrel=3.2`). Honest note: the engine
code is Arch's libalpm/pacman; LuxOS changes only names, paths and packaging.

Differences from Arch's `pacman` package:

- The internal tools are renamed and live outside `PATH` in `/usr/lib/lux/alpm/bin`:
  `lux-engine` (the transaction tool), `lux-engine-key` (keyring), `lux-engine-conf` (prints the
  effective configuration) and `lux-engine-db-upgrade`. They are small launchers that first make
  sure `/run/lux/engine.conf` is up to date, then run the real program from
  `/usr/lib/lux/alpm/libexec`. No man pages or shell completion for them.
- Default paths: config `/run/lux/engine.conf` (generated by `lux-config` from `/etc/lux/lux.conf` —
  never edit it), database `/var/lib/lux/`, cache `/var/cache/lux/pkg/`, log `/var/log/lux.log`,
  keyring `/etc/lux/keyring/`, admin hooks `/etc/lux/hooks/`. Package hooks stay in
  `/usr/share/libalpm/hooks`, keyring packages in `/usr/share/pacman/keyrings` (Arch's paths).
- Mirrors: `/etc/lux/mirrorlist` (one address per line) is part of `lux-engine`;
  `pacman-mirrorlist` is not needed. `pacman-contrib` and `expac` are not needed either
  (lux has its own cache cleaning, update check and config merge).
- `makepkg`, `vercmp`, `repo-add`, `repo-remove` and `/etc/makepkg.conf` stay as in Arch.
- `provides=(pacman libalpm.so luxos-pacman)`, `conflicts`/`replaces` `pacman` and `luxos-pacman`,
  so Arch packages depending on `pacman` keep working.

Who gets the internal tools in `PATH`:

| Caller | How |
|---|---|
| `lux`, `lux_alpm.py` and hooks/scriptlets of their transactions | prepend `/usr/lib/lux/alpm/bin` to `PATH`; via sudo/pkexec a fixed `PATH=/usr/lib/lux/alpm/bin:/usr/local/sbin:/usr/local/bin:/usr/bin` |
| `makepkg` | `/etc/makepkg.conf.d/lux-engine.conf` sets `PATH`, `PACMAN=/usr/lib/lux/alpm/bin/lux-engine` and `PACMAN_AUTH` (sudo with the same PATH) |
| `archlinux-keyring-wkd-sync` service | drop-in `archlinux-keyring-wkd-sync.service.d/lux-engine.conf` (keyring `/etc/lux/keyring`) |
| LuxOS Store, LuxOS Care, Drivers, printing, installer, sandbox | set the path themselves |

A global systemd `DefaultEnvironment` is intentionally not used (user sessions would inherit it).
`lux-engine-config.service` generates `/run/lux/engine.conf` at boot.

Signing keys from keyring packages (`archlinux-keyring`, `luxos-keyring`) are loaded by the hook
`/usr/share/libalpm/hooks/lux-engine-keyrings.hook` (runs `lux-engine-key --populate <keyring>`
after any transaction that installs or upgrades `usr/share/pacman/keyrings/*.gpg`), because the
keyrings' own install scripts call `/usr/bin/pacman-key`, which does not exist in LuxOS.

For debugging only, an assistant may call `/usr/lib/lux/alpm/bin/lux-engine -Q ...` for read-only
queries, but all changes should go through `lux`.

## The pacman hint

Typing `pacman` (or `lux -Syu`, `lux -S x` …) shows the matching lux command instead of
"command not found". The helper is `/usr/lib/lux/pacman-hint`, called from the shell's
command-not-found handler (bashrc/zshrc/lsh) and by lux for pacman-style arguments. It never
installs or runs anything and exits with code 1.

```
✦ LuxOS uses lux to manage software.
  pacman -Syu  →  lux update
  All lux commands: lux --help
```

| pacman | lux |
|---|---|
| `pacman -Syu`, `-Su` | `lux update` |
| `pacman -Syu foo` | `lux update` + `lux install foo` |
| `pacman -Sy` | `lux update` |
| `pacman -S foo` | `lux install foo` |
| `pacman -U file.pkg.tar.zst` | `lux install file.pkg.tar.zst` |
| `pacman -Ss term` | `lux search term` |
| `pacman -Si foo` | `lux info foo` |
| `pacman -Sc`, `-Scc` | `lux clean` |
| `pacman -R…` `foo` | `lux remove foo` |
| `pacman -Q` | `lux list` |
| `pacman -Q foo`, `-Qi foo` | `lux info foo` |
| `pacman -Qs term` | `lux list term` |
| `pacman -Qu` | `lux list --upgradable` |
| `pacman -Qdt` | `lux list --orphans` + `lux autoremove` |
| `pacman -Qm` | `lux list --aur` |
| `pacman -Qe` | `lux list --explicit` |
| `pacman -Ql foo` | `lux files foo` |
| `pacman -Qo file` | `lux owns file` |
| `pacman -Qk` | `lux doctor` |
| `pacman -V` | `lux --version` |

## Keeping up with Arch

`pyalpm` from Arch is built against Arch's `libalpm.so`, so `lux-engine` must follow Arch's pacman
version. `lux doctor` warns `The package manager core X is older than the one in Arch Linux (Y); a LuxOS
update will follow`. If `pyalpm` is unusable in the meantime, lux falls back to the internal tool
`lux-engine` automatically. Check the backend: `/usr/lib/lux/lux_alpm.py --verbose available`. Force
the fallback: `LUX_BACKEND=engine lux …`.

## Migration from LuxOS 0.9

LuxOS 0.9.0 shipped `luxos-pacman`; since 0.9.1 the engine is `lux-engine`, which `replaces` it.
`lux update` swaps it automatically. Since 0.9.2, `lux` and LuxOS Care depend on the virtual
`pacman` so older installs update without "unresolvable package conflicts"; the new lux then
replaces the engine.

Updating from the pacman layout (LuxOS 0.9.5 and older): the hook
`00-lux-engine-migrate.hook` (runs first, in the same transaction that installs the new
`lux-engine`) moves `/var/lib/pacman` → `/var/lib/lux`, `/var/cache/pacman/pkg` →
`/var/cache/lux/pkg`, `/etc/pacman.d/gnupg` → `/etc/lux/keyring`, `/etc/pacman.d/hooks` →
`/etc/lux/hooks`, `/var/log/pacman.log` → `/var/log/lux.log` (renames on the same filesystem; each
step can be repeated after a power loss). Old locations stay as links until the next restart so the
still running old update can finish. Custom repositories and options of `/etc/pacman.conf`
(`[multilib]`, `IgnorePkg` → `hold`, …) are converted into `/etc/lux/lux.conf`, the ranked
`/etc/pacman.d/mirrorlist` into `/etc/lux/mirrorlist`, and the lux settings of the old `lux.conf`
(`AUR=0` …) are kept. After a restart, lux (as root) removes the links and old files; copies stay in
`/var/lib/lux/migrated-from-pacman/`. Status: `/usr/share/libalpm/scripts/lux-engine-migrate status`;
manually: `sudo /usr/lib/lux/lux_alpm.py migrate --now`. `pacman-mirrorlist` and `pacman-contrib`
become unneeded and are offered by `lux autoremove`.

## Repositories

`/etc/lux/lux.conf` (LuxOS default, without comments):

```
architecture        auto
parallel-downloads  10
signatures          required
local-signatures    optional
color               on
candy               on
check-space         on
verbose-lists       on
download-user       alpm
protect             lux-engine glibc
aur                 on
review-pkgbuild     on
flatpak             on
clean-keep          2

repo luxos
    server  https://lsl.lux-ai.cz/luxos/$repo/$arch

repo luxos-apps
    server  https://lsl.lux-ai.cz/luxos/$repo/$arch

repo core
    mirrors  /etc/lux/mirrorlist

repo extra
    mirrors  /etc/lux/mirrorlist

include  /etc/lux/conf.d/*.conf
```

| Repository | Content |
|---|---|
| `[luxos]` | the LuxOS system: lux-engine, lux, luxos-desktop, luxos-care, luxos-drivers, luxos-installer, lsh, themes, branding, LuxDrop, … and legacy NVIDIA drivers (`nvidia-580xx-*`, `nvidia-470xx-*`, built from AUR, online only) |
| `[luxos-apps]` | downloadable apps, e.g. `lsl` (Lux Simple Lang), `lsl-ide`, `lux-code`, `luxai`, `luxos-docs` |
| `[core]`, `[extra]` | Arch Linux, via `/etc/lux/mirrorlist` (`lux mirrors` refreshes it) |
| `.lux` repo | `https://lsl.lux-ai.cz/luxos/lux/` (`index.json` + signatures), see [lux-packages.md](lux-packages.md) |

`[multilib]` is not enabled by default; the installer's Gaming template enables it (Steam needs it),
manually `sudo /usr/lib/lux/lux-config enable-repo multilib`. Own repositories go to
`/etc/lux/conf.d/NAME.conf` (`repo NAME` + indented `server …`).
`[luxos]`/`[luxos-apps]` are listed before Arch's repos, so LuxOS versions win on name clashes.
An overview page of the repos is at `https://lsl.lux-ai.cz/luxos/`.

The live ISO installs LuxOS packages from a local copy at `/opt/luxos-repo` (`file://` servers);
the installed system uses the online servers above.

## Signing and luxos-keyring

- Every package and database in `[luxos]`/`[luxos-apps]` is signed with the LuxOS key, fingerprint
  `FD185DAB770140E89C37275E7035CFDFDCA6C991` (marked fully trusted in `luxos-trusted`).
- The public key is in the package `luxos-keyring`:
  `/usr/share/pacman/keyrings/luxos.gpg`, `luxos-trusted`, `luxos-revoked`.
- `signatures required` (engine `SigLevel = Required DatabaseOptional`): package signatures are
  mandatory; local files (`lux install ./x.pkg.tar.zst`) follow `local-signatures optional`.
- `.lux` packages and the `.lux` index are verified with `gpgv` against the same `luxos.gpg`.
- Keyring problems: `lux fix` (re-init and re-populate the keyring, reinstall keyrings).
